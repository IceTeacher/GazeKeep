# Agent 工作流

本文补充根 `AGENTS.md`，具体架构按[文档索引](index.md)选择；文档任务加载 [任务清单](../tasks/todo.md)。

## 开始任务

- 检查工作树并保留已有改动，读取目标模块规则。
- 搜索真实入口、配置和调用方，区分当前实现、产品承诺与待验收能力。
- 复杂接口、恢复与并发变更先明确失败语义、资源所有者和验证方法，并更新相关架构。

## 执行任务

- 小步实现并运行相关检查；纯规则与缺陷先确认失败用例，硬件/UI 先定义复现场景。
- 失败先核对实现、fixture、调用栈和环境，不弱化安全断言，不以 skip 或空收集换取通过。
- 已授权的本地工作持续推进；文档任务发现产品缺口时登记待办，不顺手扩展为功能实现。

## 执行边界

设备安装、重启、系统配置和发布先核对本次授权与影响；已有授权不重复询问。需要用户决策时先完成独立的准备、验证和可审查结果，再说明具体动作与恢复方式。

## 结束任务

- 运行受影响模块门禁、文档和资产检查，以及 `git diff --check`。
- 检查敏感信息、无关生成物与工作树；报告实际结果、未运行项及原因。
- 更新[任务清单](../tasks/todo.md)，只保留未完成事项和本次验证；设备验收遵循[测试规范](testing.md)，不维护历史流水。

## 提交说明

默认不提交或推送。生成提交信息时仅分析索引；明确授权提交后复核 HEAD 与暂存快照，不用工作区版本覆盖索引。标题与分组流程分别使用对应 Skill，提交前通过现有 Hook 和 commitlint。
