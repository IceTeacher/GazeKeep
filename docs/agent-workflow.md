# Agent 工作流

本文维护协作规则与 Skills 的组织方式、执行边界及交接要求；仓库通用约束以根 [AGENTS.md](../AGENTS.md) 为准。修改功能时按[文档索引](index.md)选择相关专题。

## 目标与完成条件

从请求明确交付物、允许修改的范围和验证结果。小任务直接完成；跨模块、并发或恢复设计变更，先明确接口、失败语义、资源所有者和验收方法，再同步架构与实现。

已授权的实现、运行、检查与修复持续推进至完成条件满足。只有缺少必要输入、环境条件或操作授权时，才交接具体阻塞；先完成不受阻塞的工作。发现无关缺陷时记录证据与待办，避免扩大任务。

## 规则与资料归属

| 内容                     | 维护位置                      | 读取时机                     |
| ------------------------ | ----------------------------- | ---------------------------- |
| 通用协作与授权边界       | 根 `AGENTS.md`                | 任务开始                     |
| 模块职责、约束与门禁     | 目标路径各级 `AGENTS.md`      | 涉及该工程或模块             |
| 当前设计与长期取舍       | `docs/architecture/` 对应专题 | 改变相关行为或接口           |
| 专门工作流               | `.agents/skills/*/SKILL.md`   | 请求命中其触发条件           |
| 术语                     | `CONTEXT.md`                  | 定义或核对领域概念           |
| 未完成事项与当前验收证据 | `tasks/todo.md`               | 接续任务、核对验证或交接风险 |

目录规则只补充本层约束；Skills 链接已有专题，避免复制架构、验收矩阵或共同规则。README 面向用户，索引负责路由。修正错字或链接不要求加载整个架构、测试与发布规范。

## Skills 维护

- `description` 用短句说明具体工作与触发条件；相邻技能应能区分单条/分组提交、主机/页面/完整旅程等请求。同步 `agents/openai.yaml` 的简短描述，避免截断或扩大触发范围。
- 简单技能保持自包含；确有多个较长分支时，入口只保留共同约束和路由，将条件细节放入按需读取的参考文件。不要为短技能额外拆层。
- 保留暂存快照、安全不变量、恢复要求等影响正确性的约束；步骤顺序、输出模板和说明篇幅只在任务确有需要时固定。
- 根据实际误触发、遗漏或失败收紧指令，不为某个模型增加全仓强制流程。修改后检查代表性请求的路由、输出和授权边界；结构检查通过不等于真实代理行为已验证。

维护方向参考 OpenAI 的 [Rethinking skills and prompts for GPT-6 Astra](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)。本仓库保留跨模型适用的规则，以实际任务表现决定后续调整。

## 执行边界

本地检查与修复按根规则执行；所选门禁通过且没有未解决风险后，进入交付，不为增加测试数量重复运行。文档与无行为变更按[测试规范](testing.md#验证范围与停止条件)选择检查。

设备安装、重启、系统配置和发布先核对本次授权与影响；已有授权不重复询问。确需用户决策时，先完成可独立进行的准备与验证，再给出具体动作、影响和恢复方式。任务清单中的既往操作记录是验收证据，不代表新任务自动获得相同授权。

## 提交说明

只请求生成提交信息时，以暂存区为依据交付信息即可，不修改索引或提交。单条和分组分别使用对应 Skill；用户已明确授权提交时，在授权范围内校验并执行，无需限定授权必须出现在生成之前。

提交前复核 HEAD 与暂存快照，不能用工作区版本覆盖部分暂存内容。快照变化时重新分析；只有影响既有授权或用户指定方案时才需要重新确认。提交通过现有 Hook 与 commitlint；推送需要单独授权。

## 交付与记录

报告结果、必要的验证证据、未执行项及原因。检查 `git diff --check`、工作树、敏感信息和无关产物；任务清单维护未完成事项、本次验证及仍适用于当前候选的证据，不累积操作流水。实机记录包含对应版本与环境，产品事实不能从文档检查、fake 或构建成功推导。
