# 代理工作流

## 开始与执行

检查 git status，保留已有改动；读取根规则与目标模块规则，再按索引加载相关专题和 skill。搜索当前源码与测试，不从历史提案推断现状。

设计变更先更新活动架构；确认行为、失败与验证边界后小步实施。已授权的本地修复持续推进，失败先核对断言、fixture、调用栈与工具条件，不弱化安全断言或使用空收集换通过。

文档与工具任务仅修改约定资产；应用能力缺口登记后续工作，不能为了文档看起来完整顺手实现产品功能。设备动作和发布在已有授权内执行，超出边界时先完成准备再说明具体动作。

## 交付

运行相关模块/资产门禁，检查 git diff --check、状态、敏感数据与无关生成物。报告完成项、实际验证、未运行项及原因、剩余风险；不要把历史通过、skip 或 NO-SOURCE 写成当前验收。

向 [tasks/todo.md](../tasks/todo.md) 追加本轮记录。设备结果放 docs/testing，发布时更新 compat；任务流水不替代实机证据。

## 提交说明

默认不提交或推送。用户要求生成提交信息时仅分析索引；已明确授权本地提交时，先完成 Hook 格式化，再基于最终暂存快照生成/复核说明。HEAD 或语义内容变化必须重新核对，不能让工作区版本覆盖索引。
