# v1.1.8 迭代与发版规划

状态：已验收就绪（待合并发版）。本文件定义 `v1.1.8`（`versionCode = 10`）的目标范围、详细设计、安全边界与分包执行顺序；上一版本范围见 [v1.1.7 迭代规划](v1.1.7.md)，验收基线见 [任务清单与实测基线](todo.md)。

## 目标与发版定位

在 `v1.1.7` 完成保亮后端稳定性加固、SAF 本地配置迁移与连续注视稳态单帧快判后，`v1.1.8` 聚焦**「充电长时阅读不断流 + 平躺仰视兼容与多 ROM 后台引导」**，在不增加任何系统权限的前提下覆盖更多长时阅读与国产 ROM 场景：

- **充电阅读不断流**：支持「充电时不计保亮上限」可选开关，结合电源插拔广播与电池状态校对实现即时豁免与拔电恢复，满足桌面支架充电看文档、菜谱等长时场景。
- **平躺仰视阅读兼容与多 ROM 后台引导**：允许用户关闭「手机倒扣时暂停」门控以兼容平躺举手机仰视阅读（并在关闭时跳过加速度计采样窗口）；同时将后台运行引导由 Xiaomi HyperOS 扩展至 ColorOS、OriginOS、One UI 与 Honor/Huawei。

### 不可变安全底线

本版全部改动必须继续满足 [Android 工程规则](../../apps/app/AGENTS.md#产品安全承诺) 与 [产品、术语与隐私](../product.md#隐私与安全红线)：

1. **Unknown 等价于 Away，默认熄屏**：充电豁免仅作用于单次保亮上限（`MaxHold`），一旦转头（`Away`）、看不清（`Unknown`）或链路中断，仍必须按系统原超时熄屏。
2. **拔电即刻恢复上限兜底**：充电期间不累计非充电保亮时长；拔电后的首次保亮（`ExtendResult.Done`）必须重新记录起点并受完整 `maxHoldMinutes` 约束；拔电瞬间残留的 `BATTERY_STATUS_FULL`（`plugged == 0`）绝不误判为充电中。
3. **关闭倒扣门控仍有兜底**：关闭倒扣桌面跳过后，真正倒扣桌面时仍由接近传感器（`Pocket`）或相机全黑（`TooDark` → `TooDarkRepeatedly`）保证正常熄屏，透明桌面仍因 `NoFace` 正常熄屏。
4. **零新增敏感权限**：多 ROM 后台引导不引入任何私有包 `<queries>` 或敏感权限；非 Xiaomi ROM 统一直达系统公开应用详情页 `ACTION_APPLICATION_DETAILS_SETTINGS` 并附分 ROM 路径提示，严禁申请 `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`。

## 详细设计方案

### 一、充电时豁免单次保亮上限（`unlimitedHoldWhileCharging`）

- **归属模块**：`core`（[Config.kt](../../apps/app/core/src/commonMain/kotlin/cn/rainafter/app/gazekeep/core/model/Config.kt)、[EngineEvent.kt](../../apps/app/core/src/commonMain/kotlin/cn/rainafter/app/gazekeep/core/engine/EngineEvent.kt)、[EngineSnapshot.kt](../../apps/app/core/src/commonMain/kotlin/cn/rainafter/app/gazekeep/core/engine/EngineSnapshot.kt)、[EngineReducer.kt](../../apps/app/core/src/commonMain/kotlin/cn/rainafter/app/gazekeep/core/engine/EngineReducer.kt)、[ConfigBackupCodec.kt](../../apps/app/core/src/commonMain/kotlin/cn/rainafter/app/gazekeep/core/model/ConfigBackupCodec.kt)）、`engine`（[ConfigStore.kt](../../apps/app/engine/src/main/kotlin/cn/rainafter/app/gazekeep/engine/config/ConfigStore.kt)、[GateProbe.kt](../../apps/app/engine/src/main/kotlin/cn/rainafter/app/gazekeep/engine/gate/GateProbe.kt)、[DefaultEngineEffectRunner.kt](../../apps/app/engine/src/main/kotlin/cn/rainafter/app/gazekeep/engine/runtime/DefaultEngineEffectRunner.kt)）、`shared`（[SettingsScreen.kt](../../apps/app/shared/src/commonMain/kotlin/cn/rainafter/app/gazekeep/ui/screens/SettingsScreen.kt)、[ShowcaseDirector.kt](../../apps/app/shared/src/showcaseMain/kotlin/cn/rainafter/app/gazekeep/showcase/ShowcaseDirector.kt)）、`android`（[BackendSession.kt](../../apps/app/android/src/main/kotlin/cn/rainafter/app/gazekeep/runtime/BackendSession.kt)）、`e2e`（[DeviceSession.kt](../../apps/app/e2e/src/main/kotlin/cn/rainafter/app/gazekeep/e2e/DeviceSession.kt)、[ConfigPersistenceTest.kt](../../apps/app/e2e/src/main/kotlin/cn/rainafter/app/gazekeep/e2e/ConfigPersistenceTest.kt)）
- **设计方案**：
  1. **配置定义、备份兼容与设置页交互**：
     - `GazeConfig` 新增 `unlimitedHoldWhileCharging: Boolean = false`（`ConfigStore` 键名 `unlimited_hold_while_charging`，默认关闭）。
     - `ConfigBackupCodec` 保持 `schemaVersion = 1` 并纳入导入导出（13 个字段）；导入不含该字段的 `v1.1.7` 备份时与其余字段一致沿用 `current.unlimitedHoldWhileCharging`。
     - 在 `SettingsScreen` 第 2 张卡片「单次最长保亮」下方放置「充电时不计保亮上限」开关：当 `maxHoldMinutes == 0`（已设为无限制）时**置灰禁用**并显示禁用原因副标题，同时保留底层持久化布尔值以便改回正数上限后自动恢复；同步在 `ShowcaseDirector` 点击步骤中为设置页增加安全视口防遮挡微滚，避免第 2 张卡片新增行后影响官网演示命中 `HIDE_INDICATOR`；同步加固 `:e2e` 滚动静止检测与首帧重组点击重试以适配设置页新增行高度。
  2. **双通道充电同步与电池解析收紧**：
     - `AndroidGateProbe.parseBatteryState` 收紧为 `plugged != 0 || status == BatteryManager.BATTERY_STATUS_CHARGING`，去掉单独的 `BATTERY_STATUS_FULL` 分支，防止 100% 拔线瞬态残留 `FULL` 且 `plugged == 0` 时误豁免（插电满电或 80% 充电保护停充时 `plugged != 0` 仍成立）。
     - `BackendSession` 启动 `GazeEngine` 时以 `AndroidGateProbe.currentChargingState(context)` 初始化 `EngineContext.isCharging`，并在 `registerScreenReceiver()` 中监听无权限系统广播 `ACTION_POWER_CONNECTED` / `ACTION_POWER_DISCONNECTED` 实时投递 `EngineEvent.ChargingChanged(Boolean)`；同时每轮 `DefaultEngineEffectRunner` 经 `EngineEvent.GateResult`（`isCharging: Boolean? = null`，缺省沿用当前上下文态）传入 `GateInput.isCharging` 做周期兜底校对（含 `Skip` 分支）。
  3. **引擎豁免守卫与拔电恢复（`EngineReducer`）**：
     - 统一提取 `isHoldLimitExempt(config, context)`（`maxHoldMinutes <= 0 || (unlimitedHoldWhileCharging && isCharging)`）与 `clearHoldLimitIfExempt`，覆盖 `ChargingChanged`、`ConfigChanged`、`GateResult`、`HoldLimitReached`、`holdExpired`（含 `captureFinished`）与 `extendFinished` 全部入口；`screenOff` 跨息屏保留 `context.isCharging`。
     - 豁免生效时立即清空 `holdStartUptime = null`、`forcedYieldPending = false`，发出 `EngineEffect.CancelHoldLimit`，若原处于 `Yielded(MaxHold)` 则恢复为 `Yielded(WaitingDeadline)`，使中途插电即可解除锁定；拔电后 `isHoldLimitExempt` 转为 `false`，自拔电后的首次 `ExtendResult.Done` 重新记录 `holdStartUptime = now` 并调度完整的 `ScheduleHoldLimit(now, now + maxHoldMs)`。
     - `BackendSession.dump()` 补充输出 `unlimitedHoldWhileCharging`、`faceDownGateEnabled` 与 `isCharging`。

### 二、平躺仰视阅读兼容与多 ROM 后台省电策略引导

- **归属模块**：`core`（[Config.kt](../../apps/app/core/src/commonMain/kotlin/cn/rainafter/app/gazekeep/core/model/Config.kt)、[GatePolicy.kt](../../apps/app/core/src/commonMain/kotlin/cn/rainafter/app/gazekeep/core/policy/GatePolicy.kt)、[ConfigBackupCodec.kt](../../apps/app/core/src/commonMain/kotlin/cn/rainafter/app/gazekeep/core/model/ConfigBackupCodec.kt)、`RomBackgroundPolicy`）、`engine`（[ConfigStore.kt](../../apps/app/engine/src/main/kotlin/cn/rainafter/app/gazekeep/engine/config/ConfigStore.kt)、[GateProbe.kt](../../apps/app/engine/src/main/kotlin/cn/rainafter/app/gazekeep/engine/gate/GateProbe.kt)、[EnvironmentMonitor.kt](../../apps/app/engine/src/main/kotlin/cn/rainafter/app/gazekeep/engine/gate/EnvironmentMonitor.kt)、[DefaultEngineEffectRunner.kt](../../apps/app/engine/src/main/kotlin/cn/rainafter/app/gazekeep/engine/runtime/DefaultEngineEffectRunner.kt)）、`shared`（[SettingsScreen.kt](../../apps/app/shared/src/commonMain/kotlin/cn/rainafter/app/gazekeep/ui/screens/SettingsScreen.kt)、[PlatformActions.kt](../../apps/app/shared/src/commonMain/kotlin/cn/rainafter/app/gazekeep/ui/contract/PlatformActions.kt)、[Showcase.kt](../../apps/app/shared/src/showcaseMain/kotlin/cn/rainafter/app/gazekeep/showcase/Showcase.kt)）、`android`（[AndroidPlatformActions.kt](../../apps/app/android/src/main/kotlin/cn/rainafter/app/gazekeep/platform/AndroidPlatformActions.kt)）、`scripts/repo-tools`（[check-apk.ts](../../scripts/repo-tools/scripts/check-apk.ts)）
- **设计方案**：
  1. **倒扣门控开关与传感器短窗跳过**：
     - `GazeConfig` 与 `ConfigStore` 新增 `faceDownGateEnabled: Boolean = true`（键名 `face_down_gate_enabled`，默认开启），放入 `SettingsScreen` 第 4 张保护门控卡片（低电量阈值下方），同步纳入 `ConfigBackupCodec`（缺失字段沿用 `current.faceDownGateEnabled`）。
     - `GatePolicy.decide()` 仅在 `config.faceDownGateEnabled && input.faceDown == true` 时返回 `Skip(SkipReason.FaceDown)`。
     - 当 `faceDownGateEnabled == false` 时，`DefaultEngineEffectRunner` 调用 `gateProbe.withEnvironment(base, includeFaceDown = false)`，使 `EnvironmentMonitor` 跳过注册 `Sensor.TYPE_ACCELEROMETER`，消除平躺（`Z < -0.8`）场景下 `SensorWindow.settled()` 无效等满 `300 ms` 的延迟与功耗开销，同时保持 `Proximity`（`Pocket`）与 `Light`（`TooDarkRepeatedly`）正常采样。
     - 文案与 [product.md](../product.md#常见故障与-rom-限制) 明确说明适用前提：平躺仰视仍需基础微光（`LumaProbe >= 25`）与竖屏正对视角（`±25°` 内），全黑关灯或侧躺 90° 仍安全放行熄屏。
  2. **多 ROM 后台省电策略引导与权限守卫**：
     - 在 `core` 定义纯函数 `resolveRomBackgroundPolicy(manufacturer, brand): RomBackgroundPolicy?`，识别 `Xiaomi`（Xiaomi/Redmi/POCO/BlackShark）、`Oplus`（OPPO/Realme/OnePlus）、`Vivo`（vivo/iQOO）、`Samsung` 与 `HuaweiHonor`。
     - `PlatformActions` 以 `romBackgroundPolicy(): RomBackgroundPolicy?` 替代 `hasRomBackgroundPolicy()`；Xiaomi 系保留已真机实测直达 `com.miui.powerkeeper/.ui.HiddenAppsConfigActivity`（异常回退应用详情页）；其余尚未有真机覆盖的 ROM 家族**统一直接跳转系统公开应用详情页 `ACTION_APPLICATION_DETAILS_SETTINGS`**，并按 ROM 家族展示对应的操作路径副标题，消除硬编码未实测私有组件导致的跳错或版本失效风险。
     - [check-apk.ts](../../scripts/repo-tools/scripts/check-apk.ts) 禁止权限校验新增拦截 `ACCESS_NETWORK_STATE` 与 `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`。

### 阻断条件

- 充电豁免影响 `Away`/`Unknown` 正常熄屏、拔电后不再受 `maxHoldMinutes` 约束，或拔电瞬间满电状态误触发豁免；
- 关闭倒扣门控后，真正遮挡或暗黑环境未能正常熄屏；
- `maxHoldMinutes == 0` 时「充电时不计保亮上限」开关未置灰禁用或抹除用户原勾选值；
- 多 ROM 后台引导在目标组件缺失时崩溃而非安全回退至应用详情页，或官网 Showcase 设置页演示被新布局破坏；
- APK Manifest 引入任何禁止权限（含 `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`）。
