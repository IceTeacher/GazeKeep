# v1.1.7 迭代与发版规划

状态：已验收就绪（待合并发版）。本文件定义 `v1.1.7`（`versionCode = 9`）的目标范围、详细设计、安全边界与分包执行顺序；顺延至下一版本的功能见 [v1.1.8 迭代规划](v1.1.8.md)，交付与验收基线见 [任务清单与实测基线](todo.md) 和 [开发、测试与发布](../development.md)。

## 目标与发版定位

为确保版本稳定性，`v1.1.7` 在已完成两项保亮后端稳定性修复的基础上，仅纳入**两项低侵入高频新功能**，聚焦**「保亮后端稳定性加固 + 零权限配置迁移 + 连续注视稳态单帧快判」**，在不增加任何系统权限的前提下解决高频使用痛点：

- **已完成（已合入 `dev`）**：
  - **保亮后端告警通知时效性与限频修复**（PR #33 / #34）：恢复保亮及关闭服务时自动撤销过期告警通知；撤销通知栏告警与跨服务重配（`reconfigureEngine`）时均保留 10 分钟同类限频窗口，避免状态恢复后残留过期告警或短时重复弹通知。
  - **保亮后端切换串行化与隔离修复**（PR #33）：串行化后端切换队列并仅在转换完成后提交状态；切后端释放前先使旧检测轮次静止并取消在途延长；Shizuku `UserService` 解绑与重绑串行化并按锁隔离。
- **本版新增（待实施）**：
  - **零权限配置备份与迁移**：新增基于系统 SAF 的本地配置导出与导入，解决重装、换机或切换签名包后需要重新勾选数十个白名单/黑名单应用的痛点。
  - **连续注视稳态单帧快判（接续 Issue #14）**：在连续两轮稳定 `Looking` 进入退避稳态后，首帧若已确认 `Looking` 则提前结束本轮采样（省去 150 ms 帧间隔与第 2 帧分类耗时；首帧未通过自动回退完整 3 帧 2 票防误判），进一步压缩单次前摄开启时长。

### 范围边界（本版不做）

- **顺延至 [v1.1.8](v1.1.8.md)**：充电时豁免单次保亮上限（`unlimitedHoldWhileCharging`）、平躺仰视阅读兼容（`faceDownGateEnabled`）与多 ROM 后台省电策略引导扩充；
- **不下调 `640×480` 分析分辨率至 `480×360`**：依据 [采集与分类 ADR](../architecture/app.md#采集分类与硬件实测取舍adr)，相机启动至首帧占 `370～430 ms`，单帧分类仅 `20～60 ms`；降分辨率收益 `< 15 ms` 却会拉低标准模式睁眼概率，固定维持 `640×480`。
- 按应用独立覆盖灵敏度、提前量或保亮上限的多配置档案（留待 `v1.2.x`）；
- MediaPipe / Camera2 备用管线与暗光图像增强；
- 云端同步或跨设备网络备份（严守禁止 `INTERNET` 权限边界）。

### 不可变安全底线

本版全部改动必须继续满足 [Android 工程规则](../../apps/app/AGENTS.md#产品安全承诺) 与 [产品、术语与隐私](../product.md#隐私与安全红线)：

1. **导入不越权、不静默启用**：外部导入的配置文件绝不能恢复 `enabled = true` 或伪造 `self_test_passed_at`；未在当前设备完成两步真人自检前，一律保持关闭并要求自检。
2. **单帧快判不放宽正视与睁眼下限**：仅在连续注视稳态且首帧即判定 `Looking` 时提前结束；首帧为任何非 `Looking` 结果时，本轮立即回退至标准多帧投票，绝不将单帧异常当成通过。
3. **Unknown 等价于 Away，默认熄屏**：任何链路中断、相机失败、未知结果或后端切换异常，结果都必须是系统按原超时熄屏。
4. **零新增敏感权限**：SAF 导出/导入完全通过系统文件选择器流式读写，不申请存储权限、`INTERNET` 或 `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`。

## 详细设计方案

### 一、SAF 本地配置导出与导入（零存储权限）

- **归属模块**：`core`（[Config.kt](../../apps/app/core/src/commonMain/kotlin/cn/rainafter/app/gazekeep/core/model/Config.kt)、`ConfigBackupCodec`）、`engine`（[ConfigStore.kt](../../apps/app/engine/src/main/kotlin/cn/rainafter/app/gazekeep/engine/config/ConfigStore.kt)）、`shared`（[SettingsScreen.kt](../../apps/app/shared/src/commonMain/kotlin/cn/rainafter/app/gazekeep/ui/screens/SettingsScreen.kt)、[PlatformActions.kt](../../apps/app/shared/src/commonMain/kotlin/cn/rainafter/app/gazekeep/ui/contract/PlatformActions.kt)、`GazeKeepController`、`UiNotice`、`composeResources`）、`android`（[AndroidPlatformActions.kt](../../apps/app/android/src/main/kotlin/cn/rainafter/app/gazekeep/platform/AndroidPlatformActions.kt)、[AndroidGazeKeepController.kt](../../apps/app/android/src/main/kotlin/cn/rainafter/app/gazekeep/controller/AndroidGazeKeepController.kt)）
- **设计方案**：
  1. **备份模型与纯函数编解码（`core`）**：
     - 在 `core` 新增纯 Kotlin 编解码器 `ConfigBackupCodec`（零外部依赖的轻量结构化 JSON 读写），顶层携带 `"schemaVersion": 1`。
     - **允许导出的字段（11 项，严格对齐当前 `GazeConfig`）**：`backendLock`、`leadMillis`、`sensitivity`、`appFilterMode`、`whitelistPackages`、`blacklistPackages`、`maxHoldMinutes`、`pauseOnPowerSave`、`lowBatteryThreshold`、`debugLogEnabled`、`hideCameraIndicator`。
     - **严禁导出与恢复的字段**：`enabled`、`self_test_passed_at`、`pendingTimeoutRestore`。
     - **校验、清洗与前向兼容规则**：
       - `schemaVersion` 须为支持的正整数（当前为 `1`）；未知顶层字段安全忽略，便于未来 `v1.1.8+` 备份文件向后兼容。
       - `leadMillis`（`0..60_000` 且整秒）、`maxHoldMinutes`（`0..1_440`）、`lowBatteryThreshold`（`GazeConfig.LOW_BATTERY_LEVELS`）及枚举项按 [ConfigStore.kt](../../apps/app/engine/src/main/kotlin/cn/rainafter/app/gazekeep/engine/config/ConfigStore.kt) 同等规则校验；缺失字段保留当前配置（或默认值），类型/范围非法返回明确解析错误 `ConfigImportResult.InvalidFormat`。
       - `whitelistPackages` 与 `blacklistPackages` 在导出与导入时均仅保留符合 Android 包名规范（`^[a-zA-Z][a-zA-Z0-9_]*(\.[a-zA-Z0-9_]+)+$`，单条长度 `<= 255`）的条目，去重后单份名单上限 `500` 个，避免畸形文件膨胀 DataStore 且确保导出产物恒定小于导入字节上限。
  2. **合入策略与自检门禁（`engine` + `android`）**：
     - 导入合入时保留当前设备已有的 `selfTestPassedAt`；若当前设备尚未通过自检（`selfTestPassedAt == null`），合入后的 `enabled` 强制为 `false`；若当前设备已通过自检且服务正在运行，保留当前 `enabled` 状态并触发 `reconfigureEngine()` 应用新参数与名单。
  3. **SAF 文件选择器契约（`shared` + `android`）**：
     - `PlatformActions` 新增配置导出与导入能力（官网演示 `Showcase` 提供空实现或模拟回执）。
     - `AndroidPlatformActions` 经无状态 `SafConfigBackupCoordinator` 注册 `ActivityResultContracts.CreateDocument("application/json")`（默认文件名 `gazekeep-config.json`）与 `ActivityResultContracts.OpenDocument()`（MIME `application/json`、`text/plain`、`*/*`），支持 Activity 旋转重建后仍能完成读写并回传进程级反馈；读取限制最大字节数 `512 * 1024`（超限直接拒绝，严格覆盖双 500 项最坏合法导出体积）。
     - `SettingsScreen` 在底部工具卡片新增「导出配置」「导入配置」入口；导入前若当前已有非空名单，弹出 `OverlayDialog` 确认覆盖；导入成功或失败通过轻量提示 / `UiNotice` 反馈。

### 二、连续注视稳态单帧快判（接续 Issue #14）

- **归属模块**：`core`（[LeadBackoff.kt](../../apps/app/core/src/commonMain/kotlin/cn/rainafter/app/gazekeep/core/policy/LeadBackoff.kt)、[EngineEffect.kt](../../apps/app/core/src/commonMain/kotlin/cn/rainafter/app/gazekeep/core/engine/EngineEffect.kt)、[EngineReducer.kt](../../apps/app/core/src/commonMain/kotlin/cn/rainafter/app/gazekeep/core/engine/EngineReducer.kt)、[AttentionVoter.kt](../../apps/app/core/src/commonMain/kotlin/cn/rainafter/app/gazekeep/core/policy/AttentionVoter.kt)）、`engine`（[AttentionCaptureSession.kt](../../apps/app/engine/src/main/kotlin/cn/rainafter/app/gazekeep/engine/capture/AttentionCaptureSession.kt)）
- **设计方案**：
  - 在 `CapturePlan` 与 `LeadBackoff.CaptureSettings` 新增 `fastFirstFrame: Boolean = false`（当 `lookingStreak >= 2` 时 `fastFirstFrame = true`，`maxFrames = 3`）：
  - `AttentionVoter` 支持 `fastFirstFrame` 模式：**仅当第 1 帧即为 `FrameVerdict.Looking` 时，直接返回 `VoteState.Decided(Attention.Looking)`**（省去 150 ms 帧间隔与二次推理耗时，单轮缩短约 `170～210 ms`）；
  - **安全回退**：若第 1 帧为 `FrameVerdict.NotLooking`（例如瞬间眨眼或光线波动），**不直接判负，本轮自动回退为标准 3 帧 2 票规则（后续两帧须全为 `Looking` 才判 `Looking`，否则按原多数票判 `Away` 或 `Unknown`）**；若中途提前结束且不足两帧且首帧并非 `Looking`，仍保持 `Unknown`。

- 后端切换串行化或告警 10 分钟限频窗口在导入重配后退化；
- APK Manifest 引入任何禁止权限。
