# GazeKeep 官网 (`../../../apps/web`) 完整架构与视觉规划文档

> **项目仓库**：`https://github.com/IceTeacher/GazeKeep`
> **目标路径**：`../../../apps/web`（纳入根目录 `pnpm-workspace.yaml` 统一管理）
> **视觉对标**：[Apple iPhone Air](https://www.apple.com/iphone-air/)（设备与留白）、[Linear](https://linear.app/)（信息层级）、[Signal](https://signal.org/)（隐私表达）

## 一、 项目背景与核心目标

### 当前落地约定

官网保留 Astro 静态双语输出，在 `core/shared` 增加 Wasm 与 JS 浏览器目标；展示入口位于 shared 的 Web source set，复用真实页面与 controller/platform 契约，不连接相机或后端。桥接导出 `setScreen`、`setDemoStatus`、`setLocaleAndTheme`，首帧挂载后发送 `gazekeep:ready`，前端重放最新状态。构建按 KMP → 资源同步 → Astro 执行，生成资源忽略提交。站点统计见第六节，不启用 Partytown。本轮只本地预览。性能数字为测量目标，文案以产品定义与隐私真源为准。

内屏使用同源 iframe 隔离 KMP Wasm/JS 加载与生命周期，内部保持单 Canvas，前端只挂载一个 iframe。Wasm 能力不足或启动失败时选择 JS，最终失败提供重试；`load` 事件只表示文档加载，实际就绪以 Compose 首帧与字体加载完成后的通知为准。浏览器语言设置仅作用于展示 iframe。手机外壳与叙事使用同一实例。机身为 Three.js 实体模型（初始 416×872×40），屏幕为 392×848 的统一逻辑画布，包含顶部 40、应用 392×784 与底部 24；状态栏、挖孔和横条随整个画布等比缩放。单 DOM 内屏依据同一相机投影屏幕四角，与机身共享姿态。设备在首帧就绪前隐藏且不改变布局：实体机身按首屏倾斜姿态完成首次绘制，或确认降级后，才短暂淡入（减少动态时直接显示），脚本未运行时 4 秒后限时显示，避免闪出未投影的平铺内屏或正面降级外壳。WebGL 不可用时降级为正面 CSS 设备。桌面与常规移动端使用局部 sticky 跟随；移动端上图下文，紧凑模式随正文展示。

展示状态只通过真实页面、外壳光效与机外说明表达，不额外在 App 上方插入状态文字栏。状态栏采用同主题前景色，依次显示时钟、Wi-Fi、移动信号和电池，图标为仿 Android 原生的实心样式（属于机身仿真，不使用 Lucide）；摄像头采样环按顺时针先慢后快旋转。演示应用列表只使用开源应用与 AOSP 系统应用（GazeKeep、LSPosed、Magisk、Shizuku、SIM Toolkit、Vector），按标签排序，GazeKeep 与 LSPosed 为选中项；图标从模拟器中 GazeKeep 应用列表的实际渲染导出（明暗两次截取求透明度），LSPosed 按其开源仓库的自适应图标矢量与 Android 12+ 动态底色渲染，存于 `showcaseMain/composeResources/files/apps/<包名>.webp`，Web 适配层按 Android 端的圆角容器绘制。主页应用版本显示真实版本号：`:shared:generateShowcaseVersion` 从 `android/build.gradle.kts` 的 `versionName` 生成常量（与发布门禁读取同一来源），Android 版本与设备信息仍为演示值。内屏边缘通过同色底、裁剪与独立合成处理，避免 3D 倾斜时出现矩形接缝。

滚动采用浏览器原生滚动与局部 sticky 场景，不拦截滚轮、触摸或方向键。桌面非紧凑布局以 CSS Scroll Snap（`mandatory`）一次停靠一屏：首屏、工作流标题、三幕文案、运行方式与专注范围的文案整体为强制停靠点（`scroll-snap-stop: always`），三幕文案居中使场景进度落在整数幕；运行方式与专注范围的停靠间距与三幕相近（约一屏）。隐私至结尾区包在同一个吸附区域内，外边距向下覆盖页脚，区域高于视口时其中任意位置都是合法停靠，因此隐私及之后为普通连续滚动，也不会被强制吸附拉回展示区。吸附只决定停靠位置，姿态与内屏仍由实际滚动位置驱动；文案整体高于视口时浏览器在其内部放开自由滚动，矮视口仍能读完。吸附目标的祖先不得建立滚动容器（隐私区用 `overflow: clip`）。移动端非紧凑布局只对三幕逐幕强制吸附：三幕文案位于 sticky 面板内不能作为吸附目标，由三幕区内三个零高标记承担，脚本按实际视口高度定位到进度恰为 1、2、3 的位置；视口跨两个吸附区域不是合法停靠，因此首屏区域向下延伸到三幕区顶部（含工作流标题），运行方式区域向下覆盖到页尾，三幕之外仍为连续滚动。紧凑模式与减少动态均保持连续滚动。单手机实例贯穿首屏、三幕工作流、后端与白名单，在隐私区前释放。统一位置进度驱动三轴手机姿态、人物透明度、文案与内屏阶段，正反方向使用同一映射；阶段变化时才同步桥接。第一幕手机左移持机、文案右侧；隐私页绘制完成后手部渐隐，第二幕手机回正；第三幕手机右移并全黑，随后在后端区黑屏换页并随滚动渐亮，桌面手机固定在右侧贯穿后端区、左侧内容滚动；随后以第二幕到第三幕的镜像姿态移到专注范围左侧，范围内容靠右：横移区间从运行方式列表离开设备所在高度开始、在范围文案停靠点结束，落在吸附动画减速段；范围文案按手机实际横向位置在越过中线后淡入，手机掠过时不压住清晰文字。桌面横移以两端零速的五次缓动过渡，过程中朝运动方向侧转 18°、侧倾 4° 并缩小 4%，两端回正。移动端采用同一局部固定容器内的上图下文。减少动态、短视口或内容容纳不足时使用静态紧凑布局，保留内容与操作。

视觉采用墨黑/暖白与旧版绿色。颜色令牌集中在 `src/styles/tokens.css`，组件与脚本只引用变量：品牌色（主题绿 #14795e、按钮文字白色、手部肤色 #ed9da0）明暗共用，切换主题只改变背景、文字、面板、分隔、阴影、Shader 底色与内屏底色等表面色。深色底上主题绿对比度约 3.6:1，大字与图标可读，小号绿色文字低于 4.5:1，暂按产品要求保留。持机场景使用用户提供的粉色 SVG 手部，不显示摄影人物；掌部、拇指和指尖分层围绕真实设备。首屏恢复旧版三轴倾斜，滚出后回正。首屏 Shader 随主题更新颜色，叠加流动折射光带、噪声及指针响应；功能区收敛为低强度环境光，隐私区为静态底色。CSS 提供同主题降级，离屏、后台和减少动态时暂停。正文采用去线留白：各区段与列表不使用分隔线、底色区块或边框面板，直接置于页面底色上，以留白、字号层级和极淡强调色图标底组织。运行方式为带指示竖线的三行选项，LSPosed 与 Shizuku 使用各自开源项目的真实图标、无障碍使用主题绿圆底人形，未选中项去饱和；专注范围的应用列表只由手机内屏展示，文案下仅保留保护上限卡片（半圈刻度环、数值与设置入口，极淡强调色底）；隐私为居中标题与三项承诺，图标置于描边圆环中（参考 AndroMeld 连接方式区块的图标样式），三项之间只靠列距分组，不加连线与光晕，保留隐私真源三句与次级权限源码入口；开始使用以大号浅色序号 01–03 为锚点，常见问题为左侧停留标题与右侧问题列表，结尾区与页脚不加分隔线。公开视觉参考为 Apple iPhone Air、Linear 与 Signal，Mobbin 付费权限不可用。

Web 字体使用带 OFL 许可的 Noto CJK 字符子集，位于 showcaseMain，仅用于网页展示。官网构建过滤 source map；KMP 生成目录排除在 Astro 类型检查之外。shared 的 `webpack.config.d/public-path.js` 把 webpack `publicPath` 固定为 `./`：展示入口以 module 脚本加载，取不到 `currentScript`，自动推断会改用页面最后一个 http(s) 脚本的地址，托管方在页尾注入的脚本（如 Cloudflare Web Analytics 的 beacon）会把 `.wasm` 请求引到外站；`scripts/build.ts` 发现入口仍含自动推断运行时即中止构建。

首屏加载：`shaders/js` 的 `createShader` 会注册整个组件库，构建插件（`scripts/build-performance.ts`）在打包时把注册表裁到首屏实际使用的组件，保留列表与页面创建的图层同源于 `src/scripts/hero-shader.ts`；shaders 版本固定，升级后注册表结构变化会让构建直接失败，而不是退回全量打包。构建完成后为 Three.js 分块注入 `modulepreload`，与入口脚本并行下载，以缩短机身首帧等待；样式内联，不再单独发出阻塞渲染的请求。页面内图标使用 192px WebP，favicon 使用 32px PNG。分享元数据由 `layouts/BaseLayout.astro` 输出：生产域名在 `site.config.ts`（同时作为 Astro `site`），`canonical` 与 `og:url` 指向各语言页，`og:site_name`、`og:locale` 与 `og:locale:alternate` 齐全，Twitter 使用 `summary_large_image`；分享图为 `public/og/og-<语言>.png`（1200×630，深色主题首屏截图，约 440 KB），替代文本在双语数据的 `ogImageAlt`。首屏改版后需重新截取分享图。KMP 内屏的 Wasm 体积取决于托管端压缩：上线托管需对 `.wasm`/`.js` 启用 Brotli 或 gzip，带哈希的资源设为长期不可变缓存，无哈希的 KMP 入口用协商缓存。

### 1.1 核心定位

为 **GazeKeep**（专为缺少系统级“注视不熄屏”的 Android 设备打造的端侧离线注视保亮工具）构建兼具**产品功能叙事**与**高规格前端视觉表现力**的静态官方网站。

### 1.2 核心架构约束

1. **首要目的（功能展示）**：清晰传达 GazeKeep 的核心工作流（临近熄屏前短时采样、检测到注视自动续命、看不清默认熄屏）、三种工作后端（LSPosed / Shizuku / 无障碍）、按应用白名单与超时保护上限、以及“零网络权限、纯端侧离线”的隐私承诺。
2. **次要目的（前端炫技）**：
   - 首屏采用 `https://github.com/shader-effects-inc/shaders` 构建 WebGPU 动态交互背景；
   - 滚动视差动画融入手机设备三维翻转、跟随展示与光学边框反馈；
   - **纯前端绘制手机边框 + KMP Web 实时渲染内屏**：手机外壳由 Three.js 绘制带厚度、倒角与实体侧键的机身，屏幕内部拒绝静态截图，直接挂载 GazeKeep `shared` 模块编译出的 KMP Web (`wasmJs`) 画布，实时渲染真实的 `miuix` UI（含与 App 一致的主页/设置底栏）。访客可轻点内屏操作；页面滚动和外部卡片仍驱动内部路由与状态，访客操作后一旦滚动，内屏以转场回到当前段落指定的页面。
3. **无 CMS 与纯 SSG 构建**：不使用任何内容管理系统（CMS），不开启服务端渲染（SSR），100% 通过本地 TypeScript 强类型数据源文件（`src/data/{zh,en}.ts`）在构建期生成纯静态 HTML。
4. **国际化支持（i18n）**：支持中文（`/zh/`）与英文（`/en/`）双语静态路由构建，且与 `../../../apps/app/shared` 中的 `strings.xml` 保持单一真源对齐。

## 二、 最佳技术选型与架构决策

### 2.1 技术选型总表

| 架构维度             | 最终选型                                                      | 选型理由与工程收益                                                                                                                                                                                                                                                                                                |
| :------------------- | :------------------------------------------------------------ | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **底层 SSG 框架**    | **纯血 Astro 7 (v7.4+)**<br>_(严禁混用 React `.tsx`)_         | 1. **0 KB 前端框架运行时**：彻底抛弃 `.tsx` 孤岛水合，避免 42KB+ React 运行时税与跨孤岛通信割裂。<br>2. **极致构建性能**：基于 Vite 8 (Rolldown) + Rust 编译器 + Queued Rendering（队列渲染提速 2.4 倍）。<br>3. **原生 i18n 静态路由**：内置 `i18n` 路由配置，配合 TS 数据源直接输出 `/zh/` 与 `/en/` 静态产物。 |
| **首屏背景引擎**     | **`shaders/js`**<br>_(`shader-effects-inc/shaders`)_          | 使用官方一等公民原生 JS/TS 入口 `createShader`，无需包裹 React 组件即可直接驱动 WebGPU 管线；针对不支持 WebGPU 的浏览器提供纯 CSS 径向渐变平滑降级。                                                                                                                                                              |
| **滚动视差与动画**   | **原生连续滚动 + requestAnimationFrame**                      | 原生滚动保留输入与惯性；统一进度控制手机、人物和文案，阶段变化向 KMP 展示页发送路由和状态。                                                                                                                                                                                                                       |
| **样式与手机壳绘制** | **Tailwind CSS v4 + Three.js**                                | 实体圆角机身、倒角、侧键与金属光照；单个 DOM 内屏由同一相机四角投影驱动，CSS 提供 WebGL 降级。                                                                                                                                                                                                                    |
| **手机内屏渲染**     | **Compose Multiplatform Web**<br>_(`wasmJs` 优先，`js` 兜底)_ | 复用 `../../../apps/app/shared` 下基于 `miuix` 的 `commonMain` UI 代码，注入轻量级 Mock 状态契约，通过同源 iframe 的 `window.GazeKeepWebShowcaseBridge` 供前端原生 TS 调度。                                                                                                                                      |

### 2.2 为什么坚持“纯血 Astro 7（无 `.tsx`）”而非混合孤岛？

在包含 **WebGPU Shader + 全程跟随滚动的手机外壳 + KMP WASM 画布 + 交互式后端卡片** 的连续状态机页面中：

- 若拆分为多个 React `.tsx` 孤岛，跨模块联动（如点击第 3 模块的 Shizuku 卡片去切换第 2 模块固定的 KMP 手机画布）需要绕道全局事件总线，且仍需付出完整 React 运行时体积；
- WebGPU、Skiko WASM 和滚动姿态 均为**命令式（Imperative）**操作 DOM 与 GPU 上下文，原生 Astro `<script>`（由 Vite 8 直接打包的 TypeScript 模块）能以零中间层开销直接调度它们，彻底规避 React 生命周期重渲染带来的 Canvas 闪烁或上下文重建。

### 2.3 GPU 资源与错峰挂载策略

1. **首屏与内屏的 GPU 算力接力 (`IntersectionObserver`)**：
   - 当用户位于首屏时，`shaders/js` 满帧运行；
   - 当用户向下滚动离开首屏时，`IntersectionObserver` 立即调用 `shaderInstance.pause()` 挂起首屏 WebGPU 渲染循环，减少首屏渲染与 KMP 手机内屏、视差动画的竞争。
2. **KMP WASM 错峰懒加载 (`requestIdleCallback`)**：
   - 首屏加载瞬间，手机屏幕内先展示与 `miuix` 浅色/深色背景一致的极简 SVG 骨架屏；
   - 通过 `requestIdleCallback` 在首屏渲染完成后的空闲窗口异步拉起 Skiko/KMP WASM 脚本，降低对首屏加载的影响。
3. **全站单实例 KMP Canvas 复用**：
   - 全站仅维护 **1 个** KMP 展示 iframe，iframe 保持 `inert` 与 `pointer-events: none`，不接收焦点、滚轮或触摸；内屏上方的页面层透明命中层承接指针，滚轮与竖向滑动交给页面原生滚动，只把轻点转发进画布。所有模块的界面变化均通过 JS 桥接函数在同一实例内切换路由与状态。
4. **不启用 `COOP/COEP` 跨源隔离头**：
   - 保持标准静态托管响应头，避免开启 `Cross-Origin-Embedder-Policy: require-corp` 导致 GitHub Star 徽章、外部头像等第三方图片资源被浏览器拦截。

## 三、 全站 7 大模块与前端视觉效果规划

### 模块 1：Hero 首屏 —— 「目光所及，屏幕常明」 (The Gaze-Reactive Hero)

## 四、 Monorepo 目录结构与纯 TS 数据源工程设计

### 4.1 当前目录与数据流

`apps/web/src/components/Website.astro` 只组合页面：`layouts/BaseLayout.astro` 负责文档头与首帧主题脚本，`components/site/` 为导航、主题按钮与页脚，`components/sections/` 按页面顺序各一个区块组件，`components/device/` 为手机舞台与握持层；界面图标统一使用 `@lucide/astro`，构建期内联为 SVG；手机状态栏的仿原生图标例外。`src/data/schema.ts` 约束 `zh.ts`、`en.ts` 的内容（区块眉题等零散文案在 `ui` 字段）及演示路由。`src/styles/global.css` 是样式入口，按 Tailwind 入口（`tailwind.css`，也是 oxfmt 类名排序读取的唯一样式表，不得引入其他局部文件）、令牌（`tokens.css`）、基础（`base.css`）、`sections/` 下各区块、滚动吸附（`scroll-snap.css`）与动效（`motion.css`）的顺序导入。`src/scripts/orchestrator.ts` 组合各模块并管理 KMP 桥接，`theme.ts`/`theme-switch.ts`/`theme-transition.ts` 管理主题偏好、按钮与揭示动画，`hero-backdrop.ts` 管理首屏 Shader，`site-chrome.ts` 管理导航、菜单、常见问题与重试命中层，`scroll-reveal.ts` 管理滚动显现；`story-scroll.ts` 与 `story-motion.ts` 管理原生滚动位置、统一姿态和内屏阶段；`phone-display.ts` 管理实体机身与 DOM 屏幕投影，`phone-geometry.ts` 维护统一尺寸与投影变换，`grip-geometry.ts` 维护握持坐标与前后 SVG 层的统一投影。`scripts/build.ts` 先构建 shared 的 Wasm/JS 展示资源，`sync-kmp-strings.ts` 从 Compose 资源生成双语隐私文案，随后 Astro 静态构建；`dev` 和 `check` 也先同步隐私文案。

### 4.2 KMP 展示桥接

`apps/app/shared/src/showcaseMain/kotlin/.../Showcase.kt` 提供固定演示数据、路由和状态；JS/Wasm 平台入口把 `setScreen`、`setDemoStatus`、`setLocaleAndTheme` 挂在同源 iframe 的 `window.GazeKeepWebShowcaseBridge`。父页面等字体及首帧就绪事件后重放最新状态。每次 iframe 加载带独立尝试编号；旧加载的就绪或错误事件不会改变新加载状态，重复错误只处理一次。Wasm 加载失败转 JS，最终失败显示重试入口。采样时主页显示“检测中”，第二幕展示隐私页，看不清阶段用全黑遮罩覆盖内屏；后端演示状态只在后端区锁定选项，其余阶段维持自动选择。演示与 App 共用 `SettingsNavHost`（返回栈、底栏与转场），自检页需要相机，演示中不可进入；访客操作只改内存中的演示状态。

### 4.3 手机外壳与视觉调度

手机外壳由 Three.js 的实体圆角机身、玻璃面与侧键组成，内屏为一个 KMP 展示 iframe。WebGL 相机的四角投影通过单应矩阵驱动完整 DOM 屏幕，状态栏、挖孔、应用与横条整体缩放。机身按姿态/尺寸变化绘制，不建立持续旋转循环；唯一的时间驱动是首屏停留时的电影式漂移（`heroDrift`：互质周期正弦叠加的平移、约 ±4° 偏转、±2° 俯仰、±1.2° 侧倾与 3% 内的推近，从 0 起步，随滚出首屏按首屏姿态同一包络衰减为 0）。只剩漂移推动时降到约 25 帧，滚动或阻尼跟随时仍逐帧；减少动态与紧凑布局为平放不漂移，内屏加载失败显示重试时停住，后台由浏览器暂停帧回调。离屏、后台暂停，WebGL 失效后保留正面 CSS 设备。`story-scroll.ts` 根据页面位置确定叙事步骤和页面路由，`story-motion.ts` 提供正反方向共享的姿态插值。首屏 Shader 在离屏、页面隐藏或减少动态效果时暂停；不支持 WebGPU 或创建失败时由 CSS 背景降级。功能区使用原生连续滚动，手机在隐私区之前退出 sticky 范围。

## 六、当前构建与后续验收

本轮已完成双语数据、七模块页面、Three.js 实体设备、Shader/连续滚动调度、真实 miuix Wasm/JS 展示壳、语言/主题桥接、隐私资源校验和加载失败恢复。构建与维护命令见 [官网 README](../../../apps/web/README.md)，对应环境和验收结果见[任务清单](../../plans/todo.md#官网本次验证2026-10-20)。

官网部署到 Cloudflare Pages 项目 `gazekeep`，生产分支为 `main`，自定义域名与优选 IP 在 Cloudflare 与 DNS 侧维护，流水线不改动。完整构建依赖 JDK、Android SDK 与 Gradle，因此由 GitHub Actions 托管 runner 完成完整构建与门禁后，再通过 Wrangler Direct Upload 发布同一份 `dist/`：`dev` 推送发布到 `dev` 分支别名，同仓库 PR 发布到 `pr-<编号>` 别名并原地更新一条 PR 评论（PR 头提交已由成功的 push 运行验证时整次跳过，如 `dev`→`main`，以 `dev` 别名为准），`main` 推送发布生产；fork PR 只跑门禁。发布后冒烟检查根路径 302 到 `/zh/`、`/zh/` 与 `/en/` 以及两个 KMP Showcase 目录返回 200，失败只标红不自动回滚，回滚在 Cloudflare 面板对上一个部署执行 Rollback。本地 `deploy` 脚本仅作应急。根路径由 `public/_redirects` 在服务端 302 跳转到 `/zh/`，不渲染中间页；用 302 而非 301，便于以后按浏览器语言分流；`src/pages/index.astro` 只作为 `astro preview` 等不读取 `_redirects` 环境的兜底跳转页。Direct Upload 项目不能原地切换为 Git 集成；Cloudflare 构建镜像也缺少 Android SDK，所以保留 Direct Upload，由 CI 承担构建。后续验证集中于 WebGPU 实际渲染、120Hz 硬件表现、跨浏览器矩阵和 KMP 资源体积。

站点统计只针对官网，App 不联网、不接统计 SDK 的承诺不受影响，因此不另写隐私说明。`layouts/BaseLayout.astro` 在 `/zh/`、`/en/` 头部以 `defer` 加载自建 Umami 的 `/stats/script.js`（`data-domains` 为生产域名，预览与本地不计入）与会话录制 `/stats/recorder.js`（不支持域名过滤，预览部署也会录制）；站点 ID 在 `site.config.ts`，KMP 展示 iframe 不加载。Pages 的 `_redirects` 只能代理本站路径，不能像 Vercel `rewrites` 那样转发到外部域名，所以 `/stats/*` 由 Pages Function `functions/stats/[[path]].ts` 转发到 `https://umami.rainafter.cn`：保留方法、请求体与查询参数，只转发 Umami 所需请求头（不带官网 Cookie），并把访客 `CF-Connecting-IP` 写入 `X-Forwarded-For`；脚本默认把上报发往脚本所在目录，无需 `data-host-url`。Wrangler 从 `apps/web` 发布时自动打包 `functions/`，每次统计请求计入 Functions 调用额度。Pages 面板同时开启 Web Analytics，Cloudflare 会向所有 HTML（包括 KMP iframe）注入 beacon，iframe 也计一次浏览，无法按路径排除。不启用 Partytown。

## 入场与滚动动效

首屏文案由页面头部脚本设置 `data-intro` 后纯 CSS 错峰浮现；隐私、开始使用、常见问题、结尾与保护上限等带 `data-reveal` 的元素由 `scroll-reveal.ts` 在首次进入视口时显现，只有该模块运行时才隐藏未显现元素，脚本失败不会让内容消失。动画只用 `backwards` 填充，结束后回到样式表的值，不覆盖悬停过渡；三幕、运行方式与专注范围文案由滚动脚本控制透明度，不叠加显现动画。悬停与按压细节集中在 `styles/interactions.css`，只在精确指针设备上生效（避免触屏残留悬停态），键盘聚焦复用位移提示：主按钮上浮并投出主题绿柔光、按下轻微下沉；下载图标托盘不动、箭头循环下落；外链箭头朝右上探出；文字链接、页脚、常见问题与权限清单入口变为主题绿；导航图标按钮与语言切换出现圆形底色；探索入口的滚轮点循环下滑。其余微交互包括主题图标旋入、导航下划线与常见问题答案淡入。减少动态时不隐藏也不播放。

## 连续场景与移动阅读布局

场景进度统一决定路由、遮罩、姿态与文案。隐私页绘制确认后才淡出手部；隐私与后端在全黑窗口内双向换页，最新请求编号与加载尝试共同隔离过期回执。官网 JS/Wasm 桥接的 setScreen 接受可选编号，绘制完成通过 gazekeep:rendered 回执；不改 Android 行为。脚本换页立即切换、不播放转场，避免绘制回执揭开遮罩时露出半程画面。

内屏交互：`#screen-touch` 位于 `.phone-screen` 的应用区（不含状态栏与手势条），随机身投影一同变形，命中区即倾斜后的屏幕；`touch-action: pan-y pinch-zoom` 让竖向滑动与缩放由浏览器处理，滚轮直接滚动页面，叙事与吸附不受影响。`screen-touch.ts` 只跟踪首个指针，位移不超过 10px 才算轻点：按下时用 `#phone-visual` 记录的投影四角求逆单应，把视口坐标换算为应用坐标，再以合成指针事件转发给 iframe 中 ComposeViewport 开放 shadow root 内的画布。Compose 按 `offsetX/offsetY` 命中，而 Android Chrome 会把 iframe 内合成事件的 offset 除以设备像素比（Xiaomi 12 Pro 上点底栏会落到顶部卡片），所以转发时直接写入画布坐标，不依赖浏览器计算；超出阈值、取消或丢失捕获时在画布外抬起，Compose 不产生点击。内屏未就绪、显示重试或遮罩不透明度达到 0.5（黑屏换页、设备槽渐亮前）时不响应。访客轻点后记录滚动位置，页面滚动超过 24px（或外部卡片改变演示状态）时调用 `setScreen(route, revision, true)` 复位一次：演示状态回到基线并重放当前状态，页面以返回方向转场（同页时淡入）回到当前段落指定的页面，页面内的滚动与弹窗等临时状态随之丢弃。取舍：内屏中较长的列表不能单独滚动，换取滚轮与触摸始终驱动页面叙事；画布内容无可访问树，iframe 不进入 Tab 顺序。

移动端三幕共用局部 sticky 图文面板，设备区与阅读区分开，每幕保留约 65% 稳定阅读区间；三幕手机高度取可用高度的 58%（上限 460px），并以最长正文与底部留白为约束，正文随之下移。后端与范围使用文档流设备槽，不与正文同屏，手机高度取可用高度的 70%（上限 560px），尺寸切换发生在设备槽进入视口前的透明阶段；单 iframe 只改变展示位置，设备槽进入视口时由黑渐亮。短屏、大字号与减少动态使用静态阅读。导航固定顶部，不加分隔线；顶部透明，滚动后由两层伪元素交叉淡入承托模糊：首屏仍在导航下方时用约 72% 页面底色、`blur(18px)` 且向下渐隐，融入着色的 Shader 底而不形成横条；首屏离开后用约 84% 页面底色与 `saturate(1.8) blur(20px)`，避免下方彩色内容被饱和放大而改变整条导航的颜色；手机菜单展开时仅下拉面板使用高不透明度底色与模糊保证可读，支持关闭及键盘操作。

设备跟随不得由滚动脚本逐帧改写文档坐标，否则合成器先滚动、脚本后拉回，慢速滚动会出现回弹。桌面由 CSS sticky 跟随，范围从首屏覆盖至专注范围结束；移动端视口固定段使用 fixed，文档锚定段使用 absolute 且坐标不随滚动变化。脚本只更新水平位移、旋转、透明度与遮罩。

滚动帧不读取布局：文档坐标、宿主尺寸与设备平移前的左边界在尺寸变化时缓存，帧内只读滚动位置，样式与属性仅在值变化时写入；相机提示环在滚动事件中记录位置，不在其他脚本写样式后读取 `scrollY`。机身、内屏投影与手部轮廓在滚动帧内同步绘制，不晚于 CSS 平移一帧；遮挡轮廓用预存顶点和合并矩阵投影，凸包按数值去重；手部肤色为品牌令牌，明暗主题一致。水平位移与旋转以 120ms 阻尼跟随位置姿态以抹平滚轮台阶，静止后收敛到同一位置姿态并停止绘制；尺寸变化后直接对齐。重试视觉尺寸采用逻辑坐标，透明交互层保持至少 44 CSS 像素。
