## 一、 项目背景与核心目标

### 当前落地约定

官网保留 Astro 静态双语输出，在 `core/shared` 增加 Wasm 与 JS 浏览器目标；展示入口位于 shared 的 Web source set，复用真实页面与 controller/platform 契约，不连接相机或后端。桥接导出 `setScreen`、`setDemoStatus`、`setLocaleAndTheme`，首帧挂载后发送 `gazekeep:ready`，前端重放最新状态。构建按 KMP → 资源同步 → Astro 执行，生成资源忽略提交。默认无统计服务，不启用 Partytown。本轮只本地预览。性能数字为测量目标，文案以产品定义与隐私真源为准。

内屏使用同源 iframe 隔离 KMP Wasm/JS 加载与生命周期，内部保持单 Canvas，前端只挂载一个 iframe。Wasm 能力不足或启动失败时选择 JS，最终失败提供重试；`load` 事件只表示文档加载，实际就绪以 Compose 首帧与字体加载完成后的通知为准。浏览器语言设置仅作用于展示 iframe。手机外壳与叙事使用同一实例。机身为 Three.js 实体模型（初始 416×872×40），屏幕为 392×848 的统一逻辑画布，包含顶部 40、应用 392×784 与底部 24；状态栏、挖孔和横条随整个画布等比缩放。单 DOM 内屏依据同一相机投影屏幕四角，与机身共享姿态。WebGL 不可用时降级为正面 CSS 设备。桌面与常规移动端使用局部 sticky 跟随；移动端上图下文，紧凑模式随正文展示。

展示状态只通过真实页面、外壳光效与机外说明表达，不额外在 App 上方插入状态文字栏。状态栏采用同主题前景色，依次显示时钟、Wi-Fi、移动信号和电池；摄像头采样环按顺时针先慢后快旋转。示例应用在 Web 平台适配层绘制阅读、浏览器、文档三类图标。内屏边缘通过同色底、裁剪与独立合成处理，避免 3D 倾斜时出现矩形接缝。

滚动采用浏览器原生连续滚动与局部 sticky 场景，不拦截滚轮、触摸或方向键。单手机实例贯穿首屏、三幕工作流、后端与白名单，在隐私区前释放。统一位置进度驱动三轴手机姿态、人物透明度、文案与内屏阶段，正反方向使用同一映射；阶段变化时才同步桥接。第一幕手机左移持机、文案右侧；隐私页绘制完成后手部渐隐，第二幕手机回正；第三幕手机右移并全黑，随后在后端区黑屏换页并随滚动渐亮，桌面手机固定在右侧贯穿后端区、左侧内容滚动；进入专注范围前移到左侧，范围内容靠右。桌面横移以两端零速的五次缓动过渡，过程中朝运动方向侧转 18°、侧倾 4° 并缩小 4%，两端回正。移动端采用同一局部固定容器内的上图下文。减少动态、短视口或内容容纳不足时使用静态紧凑布局，保留内容与操作。

视觉采用墨黑/暖白与旧版绿色，深色强调 #80e8ca、浅色强调 #14795e。持机场景使用用户提供的粉色 SVG 手部，不显示摄影人物；掌部、拇指和指尖分层围绕真实设备。首屏恢复旧版三轴倾斜，滚出后回正。首屏 Shader 随主题更新颜色，叠加流动折射光带、噪声及指针响应；功能区收敛为低强度环境光，隐私区为静态底色。CSS 提供同主题降级，离屏、后台和减少动态时暂停。正文采用去线留白：各区段与列表不使用分隔线、底色区块或边框面板，直接置于页面底色上，以留白、字号层级和极淡强调色图标底组织。运行方式为带指示竖线的三行选项，专注范围为应用行与大号时长摘要，隐私为居中标题与三列承诺，保留隐私真源三句与次级权限源码入口；开始使用以大号浅色序号 01–03 为锚点，常见问题为左侧停留标题与右侧问题列表，结尾区与页脚不加分隔线。公开视觉参考为 Apple iPhone Air、Linear 与 Signal，Mobbin 付费权限不可用。

Web 字体使用带 OFL 许可的 Noto CJK 字符子集，位于 showcaseMain，仅用于网页展示。官网构建过滤 source map；KMP 生成目录排除在 Astro 类型检查之外。

### 1.1 核心定位

为 **GazeKeep**（专为缺少系统级“注视不熄屏”的 Android 设备打造的端侧离线注视保亮工具）构建兼具**产品功能叙事**与**高规格前端视觉表现力**的静态官方网站。

### 1.2 核心架构约束

1. **首要目的（功能展示）**：清晰传达 GazeKeep 的核心工作流（临近熄屏前短时采样、检测到注视自动续命、看不清默认熄屏）、三种工作后端（LSPosed / Shizuku / 无障碍）、按应用白名单与超时保护上限、以及“零网络权限、纯端侧离线”的隐私承诺。
2. **次要目的（前端炫技）**：
   - 首屏采用 `https://github.com/shader-effects-inc/shaders` 构建 WebGPU 动态交互背景；
   - 滚动视差动画融入手机设备三维翻转、跟随展示与光学边框反馈；
   - **纯前端绘制手机边框 + KMP Web 实时渲染内屏**：手机外壳由 Three.js 绘制带厚度、倒角与实体侧键的机身，屏幕内部拒绝静态截图，直接挂载 GazeKeep `shared` 模块编译出的 KMP Web (`wasmJs`) 画布，实时渲染真实的 `miuix` UI（屏蔽指针交互，仅由页面滚动和外部卡片触发内部路由与状态切换）。
3. **无 CMS 与纯 SSG 构建**：不使用任何内容管理系统（CMS），不开启服务端渲染（SSR），100% 通过本地 TypeScript 强类型数据源文件（`src/data/{zh,en}.ts`）在构建期生成纯静态 HTML。
4. **国际化支持（i18n）**：支持中文（`/zh/`）与英文（`/en/`）双语静态路由构建，且与 `../../../apps/app/shared` 中的 `strings.xml` 保持单一真源对齐。

## 二、 最佳技术选型与架构决策

### 2.1 技术选型总表

| 架构维度             | 最终选型                                                      | 选型理由与工程收益                                                                                                                                                                                                                                                                                                |
| :------------------- | :------------------------------------------------------------ | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **底层 SSG 框架**    | **纯血 Astro 7 (v7.4+)**<br>_(严禁混用 React `.tsx`)_         | 1. **0 KB 前端框架运行时**：彻底抛弃 `.tsx` 孤岛水合，避免 42KB+ React 运行时税与跨孤岛通信割裂。<br>2. **极致构建性能**：基于 Vite 8 (Rolldown) + Rust 编译器 + Queued Rendering（队列渲染提速 2.4 倍）。<br>3. **原生 i18n 静态路由**：内置 `i18n` 路由配置，配合 TS 数据源直接输出 `/zh/` 与 `/en/` 静态产物。 |
| **首屏背景引擎**     | **`shaders/js`**<br>_(`shader-effects-inc/shaders`)_          | 使用官方一等公民原生 JS/TS 入口 `createShader`，无需包裹 React 组件即可直接驱动 WebGPU 管线；针对不支持 WebGPU 的浏览器提供纯 CSS 径向渐变平滑降级。                                                                                                                                                              |
| **滚动视差与动画**   | **原生连续滚动 + requestAnimationFrame**                      | 原生滚动保留输入与惯性；统一进度控制手机、人物和文案，阶段变化向 KMP 展示页发送路由和状态。                                                                                                                                                                                                                       |
| **样式与手机壳绘制** | **Tailwind CSS v4 + Three.js**                                | 实体圆角机身、倒角、侧键与金属光照；单个 DOM 内屏由同一相机四角投影驱动，CSS 提供 WebGL 降级。                                                                                                                                                                                                                    |
| **手机内屏渲染**     | **Compose Multiplatform Web**<br>_(`wasmJs` 优先，`js` 兜底)_ | 复用 `../../../apps/app/shared` 下基于 `miuix` 的 `commonMain` UI 代码，注入轻量级 Mock 状态契约，通过同源 iframe 的 `window.GazeKeepWebShowcaseBridge` 供前端原生 TS 调度。                                                                                                                                      |

### 2.2 为什么坚持“纯血 Astro 7（无 `.tsx`）”而非混合孤岛？

在包含 **WebGPU Shader + 全程跟随滚动的手机外壳 + KMP WASM 画布 + 交互式后端卡片** 的连续状态机页面中：

- 若拆分为多个 React `.tsx` 孤岛，跨模块联动（如点击第 3 模块的 Shizuku 卡片去切换第 2 模块固定的 KMP 手机画布）需要绕道全局事件总线，且仍需付出完整 React 运行时体积；
- WebGPU、Skiko WASM 和滚动姿态 均为**命令式（Imperative）**操作 DOM 与 GPU 上下文，原生 Astro `<script>`（由 Vite 8 直接打包的 TypeScript 模块）能以零中间层开销直接调度它们，彻底规避 React 生命周期重渲染带来的 Canvas 闪烁或上下文重建。

### 2.3 GPU 资源与错峰挂载策略

1. **首屏与内屏的 GPU 算力接力 (`IntersectionObserver`)**：
   - 当用户位于首屏时，`shaders/js` 满帧运行；
   - 当用户向下滚动离开首屏时，`IntersectionObserver` 立即调用 `shaderInstance.pause()` 挂起首屏 WebGPU 渲染循环，减少首屏渲染与 KMP 手机内屏、视差动画的竞争。
2. **KMP WASM 错峰懒加载 (`requestIdleCallback`)**：
   - 首屏加载瞬间，手机屏幕内先展示与 `miuix` 浅色/深色背景一致的极简 SVG 骨架屏；
   - 通过 `requestIdleCallback` 在首屏渲染完成后的空闲窗口异步拉起 Skiko/KMP WASM 脚本，降低对首屏加载的影响。
3. **全站单实例 KMP Canvas 复用**：
   - 全站仅维护 **1 个** KMP 展示 iframe，设置外层容器 `pointer-events: none`（屏蔽鼠标点击与滚轮捕获，防止干扰网页滚动），所有模块的界面变化均通过 JS 桥接函数在同一实例内切换路由与状态。
4. **不启用 `COOP/COEP` 跨源隔离头**：
   - 保持标准静态托管响应头，避免开启 `Cross-Origin-Embedder-Policy: require-corp` 导致 GitHub Star 徽章、外部头像等第三方图片资源被浏览器拦截。

## 四、 Monorepo 目录结构与纯 TS 数据源工程设计

### 4.1 当前目录与数据流

`apps/web/src/components/Website.astro` 生成双语页面；`src/data/schema.ts` 约束 `zh.ts`、`en.ts` 的内容及演示路由。`src/styles/global.css` 实现布局、统一逻辑屏幕、CSS 设备降级和背景，`src/scripts/orchestrator.ts` 管理 Shader 与 KMP 桥接，`story-scroll.ts` 与 `story-motion.mjs` 管理原生滚动位置、统一姿态和内屏阶段；`phone-display.ts` 管理实体机身与 DOM 屏幕投影，`phone-geometry.mjs` 维护统一尺寸与投影变换，`grip-geometry.mjs` 维护握持坐标与前后 SVG 层的统一投影。`scripts/build.mjs` 先构建 shared 的 Wasm/JS 展示资源，`sync-kmp-strings.mjs` 从 Compose 资源生成双语隐私文案，随后 Astro 静态构建；`dev` 和 `check` 也先同步隐私文案。

### 4.2 KMP 展示桥接

`apps/app/shared/src/showcaseMain/kotlin/.../Showcase.kt` 提供固定演示数据、路由和状态；JS/Wasm 平台入口把 `setScreen`、`setDemoStatus`、`setLocaleAndTheme` 挂在同源 iframe 的 `window.GazeKeepWebShowcaseBridge`。父页面等字体及首帧就绪事件后重放最新状态。每次 iframe 加载带独立尝试编号；旧加载的就绪或错误事件不会改变新加载状态，重复错误只处理一次。Wasm 加载失败转 JS，最终失败显示重试入口。采样时主页显示“检测中”，第二幕展示隐私页，看不清阶段用全黑遮罩覆盖内屏；后端演示状态只在后端区锁定选项，其余阶段维持自动选择。

### 4.3 手机外壳与视觉调度

手机外壳由 Three.js 的实体圆角机身、玻璃面与侧键组成，内屏为一个 KMP 展示 iframe。WebGL 相机的四角投影通过单应矩阵驱动完整 DOM 屏幕，状态栏、挖孔、应用与横条整体缩放。机身按姿态/尺寸变化绘制，不建立持续旋转循环；离屏、后台暂停，WebGL 失效后保留正面 CSS 设备。`story-scroll.ts` 根据页面位置确定叙事步骤和页面路由，`story-motion.mjs` 提供正反方向共享的姿态插值。首屏 Shader 在离屏、页面隐藏或减少动态效果时暂停；不支持 WebGPU 或创建失败时由 CSS 背景降级。功能区使用原生连续滚动，手机在隐私区之前退出 sticky 范围。

## 连续场景与移动阅读布局

场景进度统一决定路由、遮罩、姿态与文案。隐私页绘制确认后才淡出手部；隐私与后端在全黑窗口内双向换页，最新请求编号与加载尝试共同隔离过期回执。官网 JS/Wasm 桥接的 setScreen 接受可选编号，绘制完成通过 gazekeep:rendered 回执；不改 Android 行为。

移动端三幕共用局部 sticky 图文面板，设备区与阅读区分开，每幕保留约 65% 稳定阅读区间；后端与范围使用文档流设备槽，单 iframe 只改变展示位置，设备槽进入视口时由黑渐亮。短屏、大字号与减少动态使用静态阅读。导航固定顶部，不加分隔线；顶部透明，滚动后由两层伪元素交叉淡入承托模糊：首屏仍在导航下方时用约 72% 页面底色、`blur(18px)` 且向下渐隐，融入着色的 Shader 底而不形成横条；首屏离开后用约 84% 页面底色与 `saturate(1.8) blur(20px)`，避免下方彩色内容被饱和放大而改变整条导航的颜色；手机菜单展开时仅下拉面板使用高不透明度底色与模糊保证可读，支持关闭及键盘操作。

设备跟随不得由滚动脚本逐帧改写文档坐标，否则合成器先滚动、脚本后拉回，慢速滚动会出现回弹。桌面由 CSS sticky 跟随，范围从首屏覆盖至专注范围结束；移动端视口固定段使用 fixed，文档锚定段使用 absolute 且坐标不随滚动变化。脚本只更新水平位移、旋转、透明度与遮罩。

滚动帧不读取布局：文档坐标、宿主尺寸与设备平移前的左边界在尺寸变化时缓存，帧内只读滚动位置，样式与属性仅在值变化时写入；相机提示环在滚动事件中记录位置，不在其他脚本写样式后读取 `scrollY`。机身、内屏投影与手部轮廓在滚动帧内同步绘制，不晚于 CSS 平移一帧；遮挡轮廓用预存顶点和合并矩阵投影，凸包按数值去重，深色手部直接使用压暗肤色而非滤镜。水平位移与旋转以 120ms 阻尼跟随位置姿态以抹平滚轮台阶，静止后收敛到同一位置姿态并停止绘制；尺寸变化后直接对齐。重试视觉尺寸采用逻辑坐标，透明交互层保持至少 44 CSS 像素。
