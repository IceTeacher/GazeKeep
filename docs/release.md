# 发布门禁

项目采用 [MIT 许可](../LICENSE)。当前具备 Debug 与 R8/资源压缩 Release 构建入口；正式签名、当前版本完整实机验收和正式分发仍受[待办](../tasks/todo.md)约束。

## 第三方与安装包

APK 内 assets/THIRD_PARTY_NOTICES.txt 记录当前 Release 解析的外部运行依赖、版本、许可链接，以及 Apache、MIT、BSD 必要文本和声明。依据实际 android-classes-jar artifact view，排除未打包的编译存根与 Xposed API；依赖变化后重新核对。Google SDK 与 ML Kit 条款独立适用，不能将项目 MIT 许可推广至它们。

最终 APK 必须检查权限、Xposed assets/META-INF、反射入口、Shizuku Provider、AIDL 和 Binder 字段顺序。ML Kit 注册器由 Manifest metadata 反射发现；库的 consumer 规则保留类，应用额外保留这些注册器的 public 无参构造器，防止 R8 full mode 移除构造器后检测组件缺失。APK 门禁从实际 metadata 推导登记类并核对 DEX 类与无参构造器，压缩运行验收仍需设备补证。现代 API 102 和 legacy 同 APK 登记；现代最低/目标版本为 102，API 100 不支持，legacy 仅用于选择旧登记的框架。更新后重启生效，关闭热重载；实际入口与钩点按设备记录，不从徽标猜测兼容性。

## Release 签名

Release 启用 R8 与资源压缩。签名从 GAZEKEEP_STORE_FILE、GAZEKEEP_STORE_PASSWORD、GAZEKEEP_KEY_ALIAS、GAZEKEEP_KEY_PASSWORD 四个环境变量读取；配置必须完整。全部未配置时产生 unsigned APK，不视为可分发版本。密码、密钥与本地签名文件不提交。

本地压缩运行验证可以使用明确标注的开发签名副本；不能将开发签名写成正式发布签名，也不能因签名不兼容卸载用户应用或清数据。

## 发布验收

- 每次交付保持 versionCode 递增，避免同版本覆盖安装复用管理器图标缓存。
- 核对七条不变量、完整实机矩阵和最新 APK；按 Android、ROM 与三后端能力记录实测范围。
- 对 Debug 与压缩 Release 执行 `pnpm verify:apk --apk <APK路径>`：检查双登记与作用域、版本与中文简介、图标引用和位图、无参入口保留、禁止权限与 compileOnly 类未打包；另核对运行依赖。
- 记录代码/APK 标识、设备与 ROM、后端/框架版本、系统超时、实际命中候选和未执行项，不从主机测试推断硬件通过。
- 每个 Release 附实测范围、未测声明、隐私三句话、Root/非 Root 启用步骤、已知限制及需要重启的入口更新。

未授权发布时交付本地可审查结果，不创建下载链接或上传安装包。

## API 102 版本验收条件

1.1.0（versionCode=2）为双入口功能更新，现代路径以 API >=102、系统进程钩子能力、系统作用域启用与重启为前提。设备记录包含代码/APK 标识、实际框架名称/版本/API、入口日志、命中候选与桥接状态；当前实际结果与未执行项以[任务清单](../tasks/todo.md)为准。

验收须分开记录管理器识别、现代或 legacy 入口加载、桥接就绪和真实注视/熄屏结果。API 100 框架不能作为现代成功证据；没有确实选择旧登记的环境则 legacy 验收记未执行。升级从原版本覆盖安装，确认用户配置保留、中文简介和新图标显示；不自动清缓存或卸载应用。

## 1.1.2 稳定性候选

候选版本为 1.1.2（versionCode=4），验证记录来自 2026-10-14 基于 `29c27a0` 的工作树，相关实现现已入库；尚未正式分发。本轮修复相机采集所有权与取消清理、自检后台返回和迟到结果隔离，以及取消后后端迟到成功更新 oracle 的问题；修复 ML Kit 注册器构造器在压缩版被移除，以及撤销相机权限后 camera FGS 粘性恢复崩溃。另修复压缩产物的现代 Hooker SAM 回调被裁剪：改为具名的前后置拦截器，由入口包保留规则保护，并在 APK 门禁逐一核对类与完整 intercept 签名。分类阈值、桥接协议与 API 102 双入口保持原有设计。

当前压缩候选使用本地 Android 开发密钥签名，启用 R8 与资源压缩，用于运行验证；正式签名材料尚未配置。二进制 SHA-256、签名证书摘要、构建环境、门禁与设备结果集中记录在[任务清单](../tasks/todo.md)，不能以开发签名候选或 1.1.0 的人工反馈宣称正式产物已通过。

拟发布说明须保留上述修复、该 APK 对应的实测范围、未测 ROM/legacy/异常路径和已知限制。Root 环境启用 LSPosed 对应作用域并重启后，确认桥接就绪；非 Root 环境先启用无障碍或授权 Shizuku 并确认后端就绪。两种环境均需完成正视→转头自检、选择白名单并打开总开关。覆盖升级先核对签名，禁止卸载或清空用户数据；系统入口更新仍需重启生效。

发布隐私文案逐字使用以下三句：

1. 只在快要熄屏时打开前置摄像头，看完立刻关闭。
2. 画面只在内存里判断是否注视了屏幕，不保存、不上传。
3. 看不清、没看清、旁边有别人，都会让屏幕正常熄灭。

当前候选的设备环境、APK 摘要、注视/转头计数和资源释放测量集中维护在[任务清单](../tasks/todo.md)。入口更新须覆盖安装并重启后核对实际系统侧代码，不能只凭旧桥接仍可连接或 Installed 日志判为通过。

实际钩点候选、完整异常与页面矩阵、三后端恢复及 legacy 仍待补齐。正式签名及其 APK 静态门禁、设备旅程完成前，开发签名候选不能作为正式分发产物；已有局部实测结果不能扩大为完整兼容性通过。
