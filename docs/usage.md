# 安装与使用

当前请从源码构建 Debug APK，见[开发规范](development.md)。minSdk 26 只表示可安装下限，不代表所有系统已验收。1.1.0（2）已获模拟器与 Xiaomi 12 Pro 指定场景的用户人工通过确认，完整异常矩阵仍待补齐，范围见[任务清单](../tasks/todo.md)。

## 首次启用

1. 安装同一包名 cn.rainafter.app.gazekeep 的 APK；debug 与 release 不能共存。
2. 授予相机权限，运行自检：正视得到「注视了屏幕」，转头得到「未注视屏幕」。没看清不算通过。
3. 保持默认白名单开启，选择需要生效的阅读/浏览应用。
4. 选择已就绪后端并开启总开关；Android 13+ 允许通知，才能看到异常提醒。

## 三种后端

| 后端    | 准备与启用                                                                |
| ------- | ------------------------------------------------------------------------- |
| LSPosed | 已有 Root/框架的用户启用模块，作用域选择系统框架并重启，回到 App 确认就绪 |
| Shizuku | 启动 Shizuku 并授权 GazeKeep；系统重启后按 Shizuku 的运行条件重新启动     |
| 无障碍  | 在系统无障碍设置启用 GazeKeep 服务，只用于事件与保亮，不读取窗口内容      |

Auto 优先 LSPosed→Shizuku→无障碍；锁定后端不可用时不改选其他后端。应用白名单按后端使用无障碍事件、Shizuku shell 查询或 LSPosed 系统查询；查询失败时前台应用为未知，不沿用旧后端缓存。

## LSPosed 入口与升级

同一 APK 提供现代 API 102 与 legacy 登记。现代框架必须支持 API >=102 和系统进程钩子；API 100（例如旧 1.9.3_mod）不在支持范围。保留 legacy 不代表现代入口失败后会自动降级，只用于确实选择旧登记且满足最低版本 93 的框架。具体兼容性以当前 APK 的实测记录为准。

更新模块后需要重启系统使新钩子生效，不支持热重载。先核对管理器识别，再从系统日志核对 `entry=modern_102` 或 `entry=legacy`，最后回到 App 确认桥接就绪；管理器勾选不证明保亮可用。缺少桥接时检查框架兼容性、系统框架作用域和重启状态，App 不据此推断框架版本。

版本号随交付递增，两个入口共用中文简介和应用品牌图。若升级后管理器仍显示旧图标，先核对已安装版本；只清理管理器图标缓存再重开，不清空 GazeKeep 用户配置。

## 当前限制与故障

- 无法开启：核对相机权限、自检是否完成、白名单是否有应用、后端是否就绪。
- 服务异常或后端掉线：查看通知与设置状态；不要用扩大系统超时掩盖失效。
- 多脸、暗光、侧脸或相机被占用：不应保亮；相机与扫码优先使用摄像头。
- 相机自检失败：确认没有其他应用占用、权限未被撤销，回到前台后重新自检。
- 保护设置不是完整验收证明：无障碍上限后的实际熄屏、真实传感器表现、Shizuku 超时恢复及压缩 APK 的设备运行仍需验收，见[任务清单](../tasks/todo.md)。

隐私固定文案见[隐私与安全](privacy-security.md)，验收范围见[测试规范](testing.md)。当前版本的完整设备验收尚未完成。
