# 安装与使用

当前请从源码构建 Debug APK，见[开发规范](development.md)。minSdk 26 只表示可安装下限，不代表所有系统已验收。最新重构后的 APK 尚缺完整实机回归。

## 首次启用

1. 安装同一包名 cn.rainafter.app.gazekeep 的 APK；debug 与 release 不能共存。
2. 授予相机权限，运行自检：正视得到「在看」，转头得到「没在看」。没看清不算通过。
3. 保持默认白名单开启，选择需要生效的阅读/浏览应用。
4. 选择已就绪后端并开启总开关；Android 13+ 允许通知，才能看到异常提醒。

## 三种后端

| 后端    | 准备与启用                                                                |
| ------- | ------------------------------------------------------------------------- |
| LSPosed | 已有 Root/框架的用户启用模块，作用域选择系统框架并重启，回到 App 确认就绪 |
| Shizuku | 启动 Shizuku 并授权 GazeKeep；系统重启后按 Shizuku 的运行条件重新启动     |
| 无障碍  | 在系统无障碍设置启用 GazeKeep 服务，只用于事件与保亮，不读取窗口内容      |

Auto 优先 LSPosed→Shizuku→无障碍；锁定后端不可用时不改选其他后端。当前各后端的应用白名单来源仍依赖无障碍事件，独立的系统/UsageStats 前台来源尚未实现。

## 当前限制与故障

- 无法开启：核对相机权限、自检是否完成、白名单是否有应用、后端是否就绪。
- 服务异常或后端掉线：查看通知与设置状态；不要用扩大系统超时掩盖失效。
- 多脸、暗光、侧脸或相机被占用：不应保亮；相机与扫码优先使用摄像头。
- 相机自检失败：确认没有其他应用占用、权限未被撤销，回到前台后重新自检。
- 保护设置不是完整验收证明：无障碍上限释放、退避、部分传感器、系统超时恢复持久化和 Release R8 仍有[任务清单](../tasks/todo.md)。

隐私固定文案见[隐私与安全](privacy-security.md)，验收范围见[测试规范](testing.md)。当前版本的完整设备验收尚未完成。
