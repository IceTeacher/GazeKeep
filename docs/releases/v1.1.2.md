# GazeKeep 1.1.2 预发布说明

版本 1.1.2（versionCode=4），首个正式签名构建，以 GitHub 预发布提供，不是正式版。完整设备验收完成前不转为正式版本。

## 签名变更

本版起使用正式签名，证书 SHA-256 见下方构建信息。此前安装过开发签名版本（1.0.0、1.1.0 或 1.1.2 候选）的设备签名不兼容，无法覆盖安装，需要先卸载旧版再安装；卸载会清除 GazeKeep 的配置，安装后需重新授权并完成自检。以后的版本使用同一签名覆盖升级。

## 更新日志

### 新增

- 安装包按 CPU 架构拆分为 `arm64-v8a`、`armeabi-v7a`、`x86_64` 三个版本，另提供通用包 `universal`；多数手机选择 `arm64-v8a`，不确定时选择 `universal`。各包签名与版本相同，可互相覆盖安装。

### 优化

- 安装包体积：原生库改为压缩存放，并移除 32 位 x86 原生库；单架构包由约 41 MB 降至约 10–11 MB，通用包约 17 MB。
- 相机采集所有权与取消清理：自检与服务交接由共享采集协调器处理，清理排空前不开始下一轮。
- 自检从后台返回后保留已通过步骤，可手动重试。

### 修复

- 取消采集或自检后，迟到的检测结果与后端成功结果不再更新状态或回灌保亮判断；旧自检会话的结果不影响新会话。
- 压缩产物中 ML Kit 注册器的无参构造器被移除导致启动崩溃，已补充保留规则。
- 撤销相机权限后，前台服务粘性恢复不再崩溃。
- 压缩产物中 LSPosed 现代入口的回调被裁剪，改为受保留规则保护的具名拦截器。

## 实测范围

以下记录来自 2026-10-14 的开发签名压缩候选（与本 APK 同为 1.1.2，但构建于更早的代码，签名不同，且为未拆分架构的单一安装包），本次正式签名的各架构 APK 未在设备上重新验收。

- Xiaomi 12 Pro（Android 14，HyperOS 2.0.6，LSPosed 2.2.1）：覆盖安装并重启后，LSPosed 现代入口加载、桥接就绪，未见回调抽象方法错误；前台与后台连续正视各 10/10 次延长亮屏，转头 10/10 次不保亮并正常熄屏；自检中按 Home 与工具栏返回后相机均已释放。
- Android 15 模拟器（API 35）：覆盖安装并重启后 LSPosed 现代入口与桥接就绪；自检中按 Home 后相机已释放。

## 未测范围

- 多 ROM、多脸、暗光、眼镜、闭眼、视频与通话、口袋或朝下、真实触摸取消、相机被其他应用抢占。
- 无障碍保亮上限到点熄屏、Shizuku 临时超时恢复、后端切换与掉线、服务被杀后恢复。
- 确实选择旧登记（legacy）的 LSPosed 框架、实际钩点候选与作用域配置。
- 完整页面矩阵：导航与旋转、明暗与大字体、日志分享与导出、应用列表失败重试。

## 隐私

1. 只在快要熄屏时打开前置摄像头，看完立刻关闭。
2. 画面只在内存里判断是否注视了屏幕，不保存、不上传。
3. 看不清、没看清、旁边有别人，都会让屏幕正常熄灭。

## 启用步骤

- Root 环境：在 LSPosed 中启用模块，作用域选择系统框架，重启系统后回到 App 确认桥接就绪。
- 非 Root 环境：在系统无障碍设置中启用 GazeKeep 服务，或启动 Shizuku 并授权 GazeKeep，回到 App 确认后端就绪。
- 两种环境都需授予相机权限，完成自检（正视得到「注视了屏幕」，转头得到「未注视屏幕」），选择白名单应用后打开总开关。

## 已知限制

- LSPosed 模块更新后需要重启系统才生效，不支持热重载；现代入口要求框架 API >=102，不支持 API 100。
- 多脸、暗光、侧脸或相机被占用时不保亮，这是预期行为。
- minSdk 26 只是可安装下限，不代表所有系统已验收。
