## 更新日志

### 新增

- 设置页应用内语言切换：设置页新增语言选择，支持在「跟随系统」、简体中文与 English 之间切换，默认跟随系统；Android 13 及以上版本与系统「应用语言」设置保持同步。
- 小米 / HyperOS「后台运行」设置引导：针对系统默认「智能」省电策略在使用相机后会冻结后台服务、导致注视保亮静默失效的问题，在设置页新增快捷入口，引导跳转系统设置将省电策略调整为「无限制」。
- 开机自动恢复屏幕超时：新增开机广播权限（`RECEIVE_BOOT_COMPLETED`）；仅在 Shizuku 临时延长超时期间重启、存在待恢复记录时，于开机后运行一次以写回原超时，不启动检测服务或相机。
- 关于页官方网站入口：关于页新增官方网站快捷入口，点击可直接访问官网。

### 优化

- 相机权限重新授权后自动恢复：先前被撤销的相机权限重新授予且应用满足开启条件时，回到前台会自动恢复注视保亮服务，无需手动重新开关总开关。
- 详细日志查看与性能：日志列表与导出文件调整为最新记录在前，导出文件添加 `.txt` 后缀以便在手机上直接打开；日志写入改为增量追加，记录较多时不再丢失，写入时不再反复读取全部日志；设置页说明中补充提示日志包含前台应用包名。

### 修复

- 使用 LSPosed 后端时，同时检测框架就绪状态可能导致应用崩溃；现已优化流程，避免同时检测时崩溃。
- 保亮后端掉线或相机权限被撤销后，首页仍错误显示为「工作中」且状态原因提示不准确；现在会如实反映实际工作状态并准确提示原因。
- Shizuku 后台服务退出或单次绑定失败后不再自动重连，导致后端保持不可用；现已支持按间隔自动尝试重新连接。
- Shizuku 临时超时退路的多项保亮与恢复问题：解决持续注视约 60 秒后仍会熄屏、以及亮屏写回原值或倒计时更新滞后导致注视中突然熄屏的问题；用户在延长期间手动修改的系统超时不再被旧记录覆盖，到达保亮上限或切换后端时也会及时恢复原值。
- 手机在锁屏状态下点亮屏幕时，因截止时间微调导致检测引擎在无需检测时反复空转消耗电量；现在会过滤微小时间偏差，避免无谓空转。
- 详细日志的时间记录取自写盘时刻导致排队积压时时间不准确，现改为记录事件实际发生的时间。
- 人脸采集中途因屏幕触摸而取消时，未在详细日志中记录中止原因；现在会正常记录中止状态，方便回溯原因。
- 正式发布包（R8 压缩构建）中详细日志与调试输出里的引擎状态名称被混淆（如显示为 `zn0` 等），导致日志无法阅读；现已调整混淆规则，保持状态名称清晰可读。
- 服务运行中切换应用语言后，常驻通知与通知渠道名称未实时切换为新语言；现在常驻通知与两条通知渠道名称会立即切换为新语言，已经弹出的提醒保持原文。

## 启用步骤

- Root 环境：在 LSPosed 中启用模块，作用域选择系统框架，重启系统后回到 App 确认桥接就绪。
- 非 Root 环境：在系统无障碍设置中启用 GazeKeep 服务，或启动 Shizuku 并授权 GazeKeep，回到 App 确认后端就绪。
- 两种环境都需授予相机权限，完成自检（正视得到「注视了屏幕」，转头得到「未注视屏幕」），选择白名单应用后打开总开关。
- 小米/HyperOS：在设置页「后台运行」把省电策略设为「无限制」。修改策略时系统会强制停止 GazeKeep，改完需重新打开一次应用。
