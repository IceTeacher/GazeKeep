# 产品定义、领域语言与隐私安全

GazeKeep（注视保亮）为缺少系统级「注视不熄屏」能力的 Android 设备提供端上短时注视检测与延后超时。兼容性取决于 Android 版本、ROM 电源管理、相机与后端能力，必须按目标环境实测验证。

## 产品目标与边界

面向长文阅读、查资料、看菜谱等「长时间注视、极少触摸」的场景。临近系统降亮或熄屏时短暂采样前摄 1～3 帧，**只有可信的单人正视才重置一次系统超时；离开、未知（看不清）和任何链路中断均默认放行系统按原超时熄屏**。

- **交付范围**：总开关、三后端自动/锁定选择（`LSPosed → Shizuku → 无障碍`）、检测提前量、灵敏度（标准/宽松）、生效范围（仅白名单应用 / 排除黑名单应用 / 全部应用）、单次最长保亮上限（含充电时不计上限选项）、省电/低电量/倒扣门控、两步相机自检、快捷设置磁贴与本地诊断日志。默认关闭、仅白名单应用且名单为空。
- **明确不做**：不做人脸注册或身份识别、不追踪视线落点、不做眼控滚动、不持续录像、不申请网络或存储权限、不接入任何云端/统计/崩溃上报服务。
- **交互基调**：克制、清晰、安静，采用 HyperOS 设置层级与 `miuix` 交互。不把调试按钮堆成主界面，不向用户暴露人脸框/欧拉角/概率，**检测到「注视了屏幕」时安静无感、绝不弹窗**，仅在服务被杀、权限丢失或后端掉线时限频发送异常通知。

## 领域语言（Domain Ubiquitous Language）

代码中内部枚举与面向用户的产品文案严格区分：

- **注视（`Looking`）**：本轮获得可信的单人正视结果，对用户表达为「**注视了屏幕**」（`Looking at screen`）。不称为身份识别或视线落点。
- **离开（`Away`）**：本轮明确未满足注视条件（无脸、脸太小、转头、标准模式下闭眼），对用户表达为「**未注视屏幕**」（`Not looking`）。
- **未知（`Unknown`）**：本轮证据不足以可信判断（多张脸、过暗、分类异常或平票），对用户表达为「**这次没看清**」（`Could not tell this time`）；**其保亮决策严格等价于 `Away`（不保亮），但保留可解释原因**。
- **延后超时（`Extend`） / 放行（`Yield`）**：`Extend` 仅为一次可信注视重置一个系统超时周期（不称“永久常亮”）；`Yield` 允许系统继续原有降亮与熄屏过程。
- **真实用户活动（`UserActivity`）**：来自触摸、按键等外部交互的活动，不包含 GazeKeep 自身的 `Extend`。
- **熄屏时刻（`screenOffAt` / `deadline`）与降亮时刻（`screenDimAt`）**：系统本轮计划超时熄屏或进入降亮的时刻。**提前量（`lead`）**指检测相对于已知 `dim`（未知 `dim` 时相对于 `off`）提前多久开始；设为 0 秒时在降亮时刻触发，未知降亮或剩余时间不足最小采样窗口时在熄屏前兜底触发。
- **本轮令牌（`token` / `seq`）**：后端或引擎分配的、仅允许当前有效轮次执行一次 `Extend` 的单次标识。
- **生效范围与名单**：决定哪些前台应用参与注视保亮（全部应用 / 仅白名单应用 / 排除黑名单应用，默认仅白名单）。白名单与黑名单分开持久化，切换范围不互相覆盖；空白名单不保亮，空黑名单等同全部应用。**系统应用**指带 `FLAG_SYSTEM` 且从未被商店更新过的预装应用，仅决定应用列表是否默认隐藏，不影响门控判定。
- **自检（`SelfTest`）**：用户依次完成「正视（`Looking`）→ 转头（`Away`）」两步验证并获得启用资格的向导流程，唯一允许展示相机预览的页面；`Unknown` 不推进步骤。
- **单次保亮上限（`MaxHold`）**：持续依靠注视保亮达到上限（默认 30 分钟，支持自定义或设为无限制）后必须强制放行熄屏一次的保护边界，仅由真实用户活动或息屏重置；开启「充电时不计保亮上限」时连接电源期间豁免该上限，拔电后即刻恢复重新计时。
- **隐私指示器（`Privacy Indicator`）与指示器豁免**：Android 12+ 前摄活跃时状态栏右上角展示的绿点。**指示器豁免**指仅在 LSPosed 后端就绪且用户显式开启实验开关时，由 `system_server` 单向过滤 GazeKeep 自身 `OP_CAMERA` 活跃通知；不影响相机出帧，也不豁免其他应用。
- **后端就绪（`Ready`）**：实际桥接与执行本次延后超时所需的能力可用；管理器勾选模块或系统列表存在不等于后端就绪。

## 隐私文案真源

1. 只在快要熄屏时打开前置摄像头，看完立刻关闭。
2. 画面只在内存里判断是否注视了屏幕，不保存、不上传。
3. 看不清、没看清、旁边有别人，都会让屏幕正常熄灭。

英文文案：

1. The front camera opens only near screen timeout and closes immediately after checking.
2. Frames are processed in memory to check whether you are looking at the screen. Nothing is saved or uploaded.
3. Unclear results, failed detection or another person in view let the screen sleep normally.

资源 `apps/app/shared/src/commonMain/composeResources/values/strings.xml` 与 `values-en/strings.xml` 中的 `privacy_line_1`～`privacy_line_3`、根 `README.md` 以及官网同步脚本必须与本节中英文逐字一致。

## 隐私与安全红线

[Android 工程规则](../apps/app/AGENTS.md#产品安全承诺) 中的十条安全承诺是不可逾越的产品底线：

- **帧不出回调**：推理只在 App 进程完成。`ImageProxy` 不离开 `ImageAnalysis.Analyzer` 回调，不保存、不长持缓冲、不写日志、不跨进程，每帧 `finally close`。唯一预览位于自检页，离页或取消立即释放。
- **严禁敏感权限与三方统计**：禁止 `INTERNET`、`ACCESS_NETWORK_STATE`、存储/相册、`QUERY_ALL_PACKAGES`、`SYSTEM_ALERT_WINDOW`、`READ_PHONE_STATE`。构建期显式剥离合并带入的网络权限；零广告、统计或崩溃上报 SDK。无障碍服务固定 `canRetrieveWindowContent="false"`，不访问 `event.source` 或窗口文本。
- **特权进程最小化与异常隔离**：`system_server` 钩子逐候选签名解析，失配不安装，回调整体捕获 `Throwable` 且连续异常熔断；PMS 锁内只做计算与 `Handler` 投递，禁止 Binder 调用、协程、DataStore、模型或文件 I/O。
- **不篡改系统设置**：唯一例外是 Shizuku `userActivity` 被拒时的 `screen_off_timeout` 临时退路，必须先同步持久化原值至 `pendingTimeoutRestore`，并在息屏、服务停止、Binder 重连或开机广播时写回确认（见 [后端架构](architecture/backends.md#shizuku-与系统超时恢复状态机)）。
- **脱敏日志与 24 小时滚动清理**：详细日志默认关闭，仅允许记录时间、前台包名、判定/门控/中止枚举、后端、是否 `Extend` 与耗时；严禁记录图像、人脸框、欧拉角、概率、设备序列号或原始系统 `dumpsys`。开启后保留在应用私有目录，超过 24 小时滚动删除，关闭或点击清空立即删除。

## 安装、启用与故障排查

### 首次启用步骤

1. **安装 APK**：同一包名 `cn.rainafter.app.gazekeep` 的不同构建签名不能共存；正式版各 ABI 包（`arm64-v8a`、`armeabi-v7a`、`x86_64`、`universal`）签名一致，可互相覆盖升级。
2. **授权与两步自检**：授予相机权限（Android 13+ 建议同时允许通知权限以接收异常提醒），进入「相机自检」依次完成正视（得到「注视了屏幕」）与转头（得到「未注视屏幕」）。
3. **配置生效范围**：默认「仅白名单应用」，勾选需要保亮的阅读/浏览应用；或改为「排除黑名单应用」，勾选视频、导航等无需保亮的应用。
4. **启用后端与总开关**：按下方表格准备任一后端，确认显示「已就绪」后打开首页总开关（或下拉控制中心添加「注视保亮」快捷磁贴一键启停）。

### 三种工作后端准备

| 后端        | 启用方式与运行要求                                                                                   |
| ----------- | ---------------------------------------------------------------------------------------------------- |
| **LSPosed** | 已有 Root 与 LSPosed（API >= 102 或旧版 >= 93）环境启用模块，作用域勾选「系统框架」并重启系统        |
| **Shizuku** | 通过无线调试或 ADB 启动 Shizuku 并授权 GazeKeep；手机重启后需按 Shizuku 要求重新启动服务             |
| **无障碍**  | 在系统「设置 → 无障碍」开启 GazeKeep；Android 13+ 若开关置灰，先在「应用信息」右上角允许受限制的设置 |

`Auto` 模式按 `LSPosed → Shizuku → 无障碍` 选用首个就绪后端；手动锁定某后端不可用时不自动切换。前台应用识别按后端分别采用系统查询、shell 查询或无障碍 Activity 事件；无法确认前台包名时在白名单与黑名单模式下均安全放行熄屏。

### 常见故障与 ROM 限制

- **小米 / HyperOS 使用系统相机后保亮失效**：系统默认「智能」省电策略会在打开系统相机后冻结后台的 GazeKeep，且退出相机后不解冻（忽略电池优化无效）。请在 GazeKeep 设置页点击「后台运行」将省电策略设为「无限制」；修改时系统会强停应用，改完需重新打开一次 GazeKeep（Xiaomi 12 Pro / HyperOS 2 实测）。
- **其他品牌 ROM 后台限制（ColorOS / OriginOS / One UI / Honor / Huawei，待各机型实机补验）**：尚无对应品牌真机覆盖，GazeKeep 设置页「后台运行」统一引导至系统公开「应用信息」页，由用户按提示前往电池/耗电管理开启后台运行与自启动（OPPO/OnePlus/Realme 设为允许后台行为与自启动；vivo/iQOO 允许后台高耗电；Samsung 电池设为「不受限制」；Honor/Huawei 应用启动管理改为手动允许后台活动）。
- **平躺举手机仰视阅读被暂停**：默认「手机倒扣时暂停」在屏幕朝下倾角较大（归一化 `Z < -0.8` 持续 `300 ms`）时跳过检测；常平躺仰视阅读可在设置页关闭该开关。注意关闭后仍受基础亮度（`Y >= 25`）与竖屏正对视角（`±25°`）约束，完全关灯全黑或侧躺 90° 时仍会让屏幕安全熄灭。
- **无障碍开关置灰提示「受限制的设置」**：Android 13+ 对非商店安装的 APK 默认限制无障碍授权，点击后端页引导进入系统「应用信息」，在右上角菜单允许受限制的设置后再返回开启。
- **LSPosed 模块升级或未就绪**：更新 APK 后必须重启系统使新钩子生效（不支持热重载）；API 100 框架不在支持范围。若升级后管理器仍显示旧图标，仅清理管理器图标缓存即可，切勿清空 GazeKeep 应用数据。
- **无障碍后端前台未更新**：无障碍仅将能经 `PackageManager` 解析为启动器可见应用 `Activity` 的窗口事件视为前台切换（过滤悬浮窗、输入法与传送门）；从启动器应用跳入无桌面入口的系统全屏页时可能沿用上一包名，需高精度前台识别时建议使用 Shizuku 或 LSPosed。
