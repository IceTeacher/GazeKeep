# 单条提交信息

为当前暂存区的全部变更生成一条可直接使用的提交信息。生成阶段只读，不更改暂存区，也不提交。

## 分析与格式

1. 在仓库根目录读取 `commitlint.config.cjs`，并查看最近 8 条非合并提交标题（`git log -8 --no-merges --format=%s`）。配置决定允许的类型、范围和 emoji 映射；历史仅用于参考语义、范围选择和中文措辞风格。
2. 用 `git status --short --branch`、`git diff --cached --stat`、`git diff --cached --name-status` 和 `git diff --cached` 分析暂存内容。不要把未暂存或未跟踪的改动算进提交信息。需要读取某个已暂存文件的准确内容时，读取索引版本，不要依赖含有额外未暂存编辑的工作区版本。
3. 暂存区为空时，明确报告没有可生成提交信息的暂存变更；不要回退到未暂存内容。
4. 从变更的主要用户可见行为或修复结果确定一个类型和一个有效范围。新提交优先使用配置中当前交互选项提供的类型和范围；不要照搬仅为历史兼容而保留的类型或范围。
5. 标题使用 `type(scope): emoji 中文描述`。描述要概括实际行为或结果，不要只罗列文件名。
6. 根据变更规模决定是否补充正文：
    - 单一文件、单一行为且影响范围明确时，只生成标题和一句语义依据。
    - 变更跨多个模块，或同时涉及契约、迁移、生成物、实现、测试、任务记录中的多项，或包含多个相互关联的修复点时，生成标题和 2～5 条正文说明。正文每条使用 `- ` 开头，先标明子系统或改动面，再说明关键实现、行为结果或验证覆盖；需要时说明错误收敛、权限边界、幂等或恢复语义。不要把文件名清单当作正文。
    - 正文应优先说明用户可见结果、根因修复、关键技术变化和测试/验收记录；信息不足时只写能从暂存区确认的内容，不要推测。
7. 在仓库根目录用 `pnpm --config.verify-deps-before-run=false exec commitlint --edit <说明文件>` 校验候选标题。若校验失败，按输出修正后重验；若工具不可用，说明未能验证，不要声称已通过。

## 提交边界

- 默认只展示一条提交信息和一句简短的语义依据，然后等待用户确认。展示后不得运行 `git commit`。
- 用户已明确授权本地提交时无需重复确认；仍须先完成 Hook 格式化，基于最终索引生成并校验标题。仅生成说明的请求不授权提交。
- 用户确认后，提交前复查当时的 HEAD 和暂存差异与生成提案时一致。提案时记录 `HEAD` 与 `git diff --cached --binary` 的摘要供复核。状态不一致时先停止提交，按最新快照重新生成；已有授权覆盖新内容时继续核对，只有语义或范围超出授权时才重新确认。
- 确认有效且暂存内容未变时，直接提交暂存区快照，不要先 `git add`。只执行本地 `git commit`，不推送。
- 用户要求修改标题时展示最终版本；已有明确提交授权继续有效，未授权时仍只展示。

## 输出

小变更输出：

```text
<type(scope): emoji 中文描述>
```

较大变更输出完整提交说明：

```text
<type(scope): emoji 中文描述>
- <子系统或改动面：关键实现与行为结果>
- <子系统或改动面：关键实现与行为结果>
- <错误处理、测试或任务记录：验证覆盖与收敛结果>
```

随后用一句话说明标题概括的核心改动。较大变更时，这句话补充正文覆盖的范围；不要声称已提交，除非实际提交已成功。

## 本仓库入口

提交标题配置以根 commitlint.config.cjs 为准；新 scope 从 Gradle 模块派生。完整多行说明写入临时文件，不以 shell 拼接正文。门禁见[开发规范](../../../docs/development.md)，完成记录追加到 tasks/todo.md。

Hook 可以格式化并重新暂存当前文件，但不授权引入未暂存语义改动；提交前先让已授权的格式化完成，再复核索引与生成说明。HEAD 或语义内容变化时重新生成；工具失败、恢复冲突或分组路径含未暂存编辑时停在可审查结果，不顺手重置暂存区。

生成阶段禁止隐式安装依赖；commitlint 不可用时报告未校验。仓库 .npmrc 禁用 pnpm 自动安装，独立临时目录也显式传上述配置。
