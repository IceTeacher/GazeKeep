# 实机完整旅程

## 框架与职责

验证 APK 安装后页面、相机、引擎与后端连接的真实行为，包括实际熄屏与恢复。按[实机矩阵](../../../docs/development/testing.md#实机完整矩阵)选择场景并读取目标后端架构；发布验收覆盖完整矩阵，局部修复聚焦受影响路径。web 为纯静态站点，没有 E2E 层。

- 自动化：自插桩模块 `e2e`（独立进程，可撤权与强停被测应用）使用 androidx.test 与 UiAutomator，覆盖可脚本化旅程，如冷启动与配置回读、权限拒绝/撤销、后端切换与未就绪原因、Shizuku 原系统超时写回。断言读取用户可见状态与系统实际值（`settings`、Wakefulness），不读取帧或人脸数据。
- 人工矩阵：需要真人注视、闭眼、多脸、暗光、口袋、相机抢占或 ROM 特有行为的场景，按矩阵记录计数与耗时。
- 实机套件不进入默认 `pnpm test`，入口见[测试规范](../../../docs/development/testing.md#实机入口)。fake 与主机测试不证明硬件兼容。

## 环境与授权

- 核对设备、代码/APK、ROM/Android、后端/框架版本、权限、系统超时、作用域和配置；按能力选设备，不指定优先机型。
- 安装、运行 instrumentation、重启与系统设置修改须有本次授权，已有授权不重复询问；高风险钩点场景须有恢复方法。缺设备、权限或框架明确记未执行，不套用旧 APK 结果。
- 测试只在测试开始前记录、结束后恢复自己修改的设置；不清空应用数据，不卸载用户安装的版本。

## 关键证据

- 成功路径连接真实组件；不 Extend 不能替代 Hold 释放与实际熄屏。
- 涉及 Shizuku 恢复时验证原系统超时写回；涉及 LSPosed 时核对实际入口、签名、旧 seq 与作用域行为。
- 阈值变更使用[分类计数场景](../../../docs/development/testing.md#分类与页面场景)，只留计数与耗时。

## 清理与记录

恢复临时配置与服务状态；失败报告残留及恢复方法。按[记录要求](../../../docs/development/testing.md#记录与验收状态)交付本次结果、缺失条件和版本证据；发布说明引用对应版本实测范围及实际命中候选。

不保存人脸、截图中的相机画面、概率/角度、序列号或原始 dumpsys；样本只保留所需 power 字段并脱敏。ADB 与 instrumentation 不改变 APK 禁止 INTERNET 的承诺，测试 APK 的权限不得合并进主 APK。
