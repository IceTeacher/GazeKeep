# 真实完整旅程

## 框架与职责

真实组件验证 Android 页面到相机、引擎和后端的完整行为，覆盖系统熄屏及恢复。先读[测试规范](../../../docs/testing.md)和目标后端架构；fake 与主机测试不代表硬件兼容。apps/web 尚无网站或 E2E 入口，不引入云服务和浏览器编排。

## 环境与预检

- 核对设备、代码/APK 版本、ROM/Android、后端/框架版本、权限、系统超时、作用域和配置；按能力选择设备，不指定优先机型。
- 核对用户对安装、重启和系统操作的既有授权，先准备可审查版本；已授权动作不重复询问。
- 缺设备、权限或框架时明确未执行，不换 fake 冒充成功，不套用旧 APK 结果。

## 测试行为

- 验证可信正视、转头/Unknown、多脸、暗光、触摸取消、相机占用、后端切换/掉线和最大保亮。
- Shizuku 验证写入失败、服务重启、Binder 重连及息屏后的原超时恢复；LSPosed 验证错误签名、旧 seq 与禁用作用域。
- UI 与后端成功路径必须连接真实组件；主机不 Extend 不能替代 Hold 释放与实际熄屏。
- 阈值变更运行分类计数场景，只保留计数与耗时，不保存人脸图像或特征。

## 清理与记录

恢复本次临时配置与服务状态；清理失败报告残留和恢复方法，不擅自清空应用数据。错误钩点等高风险场景必须有恢复方法并核对授权。

按测试规范记录日期、代码/APK、设备环境、前提、预期、实际与未执行原因；任务清单维护本次结果，发布说明给出该版本的实测范围和实际命中候选，不累积历史流水。

不保存人脸、概率/角度、序列号或原始 dumpsys；样本只保留所需 power 字段并脱敏。ADB 连接不改变 APK 禁止 INTERNET 的承诺。
