# 文档维护与渐进式加载

## 何时加载

创建、修改、评审、删除或重命名文档时加载；普通代码任务需要文档时也按索引路由，不默认读取整个 docs。

## 渐进式加载

1. 读取根 AGENTS.md，再沿目标路径由外到内读取所有已有的目录 AGENTS.md；例如修改 apps/app 模块时，依次读取根、apps/app 与模块规则，不跳过中间层。
2. 读取 [docs/index.md](../../../docs/index.md)，只选择任务触发条件命中的页面。
3. 活动架构维护当前设计与有效取舍，代码和测试证明现状；实现差距不能豁免安全承诺。

## 更新规则

- 同步索引路径、加载条件、状态与最后复核日期，采用分类五列表格和反引号相对路径。
- 只维护当前内容；删除历史流水和重复导航前，将有效规则并入对应专题，未完成风险放入 [tasks/todo.md](../../../tasks/todo.md)。更新全部引用，不创建空归档或占位计划。
- 将来确有活动计划时使用 YYYYMMDD-slug.md；唯一“最后维护：YYYY-MM-DD”与文件前缀、索引复核日一致，表示最后实质维护日。纯机械路径调整不推进日期。
- 术语只在 CONTEXT.md，README 服务用户，AGENTS 服务代理；隐私三句以 privacy-security.md 为真源，与资源逐字一致。
- 当前实现、目标、主机通过、实机通过和未执行分别表达，不用旧版本证据声称新版通过。

## 完成检查

```bash
pnpm verify:docs
pnpm verify:agent-assets
git diff --check
```

失败先修复引用、登记、元数据或内容，不删登记或放宽检查掩盖错误。任务清单只保留未完成项与本次真实验证。
