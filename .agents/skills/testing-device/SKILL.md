# 实机与完整旅程

先读[完整矩阵](../../../docs/testing.md)、对应后端架构和[已测系统](../../../docs/compat/tested-systems.md)。M0 阈值变更必须重跑计数表，不用 fake 冒充兼容验收。

## 前提与执行

- 确认设备/APK 与代码版本、机型/ROM/Android、后端/框架版本、权限、系统超时、作用域和当前配置；未知版本不推测。
- 先核对用户已经授权的设备安装、重启与系统操作。需要真实副作用时先准备可审查版本；已有授权不重复询问。
- 根据风险选矩阵，至少覆盖可信正视、转头/Unknown、触摸取消、相机占用、切换/掉线、最大保亮、Shizuku 恢复、错误签名或 seq。UI 与后端成功路径必须连接真实组件。
- 缺设备、权限或框架在预检记录未执行，不自动换 fake、不把旧 APK 历史通过算当前通过。
- 临时配置与服务在结束时恢复到用户原状态；清理失败报告残留与恢复方式，不擅自清空应用数据。高风险错误钩点版本保留可恢复方法并核对授权。

## 证据

追加 docs/testing 记录，包含日期、代码/APK、前提、预期、实际结果与未执行原因；发布更新 compat 的实际命中候选。主机通过与实机通过分开，后续记录不能改写历史。

不保存人脸图片、画面、概率/角度、序列号或 dumpsys 原始输出；样本只保留所需 power 字段。手机联网或 ADB 连接不改变 APK 禁止 INTERNET 的产品承诺。
