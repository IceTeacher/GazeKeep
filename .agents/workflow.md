# Agent 工作流

本文维护协作规则与 Skills 的组织方式、执行边界及交接要求；仓库通用约束以根 [AGENTS.md](../AGENTS.md) 为准。修改功能时按[文档路由](docs-index.md)选择相关专题。

## 规则与资料归属

| 内容                     | 维护位置                                       | 读取时机                     |
| ------------------------ | ---------------------------------------------- | ---------------------------- |
| 通用协作与授权边界       | 根 `AGENTS.md`                                 | 任务开始                     |
| 模块职责、约束与门禁     | 目标路径各级 `AGENTS.md`                       | 涉及该工程或模块             |
| Agent 流程与文档路由     | `.agents/workflow.md`、`.agents/docs-index.md` | 维护规则或选择任务资料       |
| 当前设计与长期取舍       | `docs/architecture/` 对应专题                  | 改变相关行为或接口           |
| 专门工作流               | `.agents/skills/*/SKILL.md`                    | 请求命中其触发条件           |
| 术语                     | `CONTEXT.md`                                   | 定义或核对领域概念           |
| 未完成事项与当前验收证据 | `docs/plans/todo.md`                           | 接续任务、核对验证或交接风险 |

目录规则只补充本层约束；Skills 链接已有专题，避免复制架构、验收矩阵或共同规则。README 与 docs/ 面向用户和贡献者，docs/index.md 提供阅读入口；.agents/docs-index.md 维护 Agent 路由与复核登记。任务与计划统一放在 docs/plans/，不按进行中、已完成等状态拆分目录或索引栏目。修正错字或链接不要求加载整个架构、测试与发布规范。

## Skills 维护

`.agents/skills/` 是仓库 Skill 的维护真源；`.claude/skills/` 是 Claude Code 的发现适配层，必须与真源保持一一对应并通过 `verify:agent-assets`。新增或修改 Skill 时同步更新适配层，不在两处分别维护规则。

- `description` 用短句说明具体工作与触发条件；相邻技能应能区分单条/分组提交、主机/页面/完整旅程等请求。同步各 Skill `agents/openai.yaml` 的简短描述，避免截断或扩大触发范围。
- 简单技能保持自包含；确有多个较长分支时，入口只保留共同约束和路由，将条件细节放入按需读取的参考文件。不要为短技能额外拆层。
- 保留暂存快照、安全不变量、恢复要求等影响正确性的约束；步骤顺序、输出模板和说明篇幅只在任务确有需要时固定。
- 根据实际误触发、遗漏或失败收紧指令，不为某个模型增加全仓强制流程。修改后检查代表性请求的路由、输出和授权边界；结构检查通过不等于真实代理行为已验证。

维护方向参考 OpenAI 的 [Rethinking skills and prompts for GPT-6 Astra](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)。本仓库保留跨模型适用的规则，以实际任务表现决定后续调整。

## 执行流程

1. **任务分类**：确认交付物、修改范围、可观察验收和主要风险。按任务选择默认验证：文档/格式、纯逻辑/协议、UI/视觉、设备/权限/后端、跨模块/发布。具体测试层次、命令和真实环境限制以[测试规范](../docs/development/testing.md)为准；普通小任务不要求完整计划。
2. **按需读取**：读取根规则、目标路径最近的 `AGENTS.md`，再按[文档路由](docs-index.md)加载与风险直接相关的专题和 Skill。已读且未变化的规则不重复读取，不加载无关的全仓文档。
3. **实现**：保留用户改动和授权边界；同步受影响的接口、调用方、测试和文档。规则修改以 `.agents/skills/` 为真源，逐字同步 `.claude/skills/`；不把目标设计、主机通过或旧版本结果写成当前实现事实。
4. **最小充分验证**：按任务分类运行最小充分门禁，覆盖本次风险。检查失败、后续改动或具体风险未解决时才扩大或重跑；不删断言、弱化安全断言、无理由 skip 或用 fake、构建、`NO-SOURCE` 替代真实环境证据。设备安装、重启、系统配置和发布先核对授权与恢复方式。
5. **证据交付**：报告**改动**、**已验证**、**未执行/原因**、**剩余风险**；测试、设备和发布记录包含实际版本与环境，需要交接时给出可复现命令、当前状态、残留物和恢复方式。

## 提交说明

只请求生成提交信息时，以暂存区为依据交付信息即可，不修改索引或提交。单条和分组分别使用对应 Skill；用户已明确授权提交时，在授权范围内校验并执行，无需限定授权必须出现在生成之前。

提交前复核 HEAD 与暂存快照，不能用工作区版本覆盖部分暂存内容。快照变化时重新分析；只有影响既有授权或用户指定方案时才需要重新确认。提交通过现有 Hook 与 commitlint；推送需要单独授权。
